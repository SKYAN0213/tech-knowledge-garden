#### [AWS, AgentCore 공동 인프라에서 고객 데이터·메모리·비용을 나누는 예제 공개](https://skyan0213.github.io/tech-knowledge-garden/news/b58cbd8dc63e6f59)

발표 2026-06-24

연구·기술 · 구현·운영 지침 · AWS

AWS는 2026년 6월 24일(한국시간), Amazon Bedrock AgentCore로 여러 고객이 인프라를 공유하면서 데이터를 분리하는 구현 예제를 공개했다. 진료소·병원을 가정한 예제에서 서비스 등급·고객·사용자 계층에 따라 문서 검색, 에이전트 기억, 모델 사용과 비용 추적을 구성했다.

##### 검색·도구·메모리의 고객 범위

Cognito 토큰의 서비스 등급과 clinic\_id를 고객 문맥으로 전달한다. 서비스 등급별 S3 버킷 안의 고객 경로로 문서를 나누고, Knowledge Base 검색에는 clinic\_id 메타데이터 필터를 적용한다.

Gateway는 Lambda의 patient\_context·clinic\_config 함수를 MCP 도구로 제공한다. 고객 문맥을 헤더로 전달하며, 도구 Lambda는 고객 태그를 가진 임시 자격증명으로 DynamoDB의 접근 범위를 제한하는 패턴을 사용한다.

메모리는 서비스 등급·clinic\_id·사용자 ID를 합친 actor\_id와 이름공간으로 구분한다. 실행 시 얻는 임시 자격증명에 같은 세 가지 태그를 넣어 접근 범위를 제한한다.

##### 서비스 등급 비용과 고객별 토큰 사용량

서비스 등급마다 Bedrock Project와 비용 태그를 두고 추론 요청에 프로젝트 ID를 전달한다. 고객별 사용량은 clinic\_id·모델·입출력 토큰을 구조화 로그로 기록하며, 비용은 토큰 수와 모델별 단가로 추산하는 방식이다.

##### [Transformers.js, 해시로 모델 파일을 공유하는 Cross-Origin Storage 실험 소개](https://skyan0213.github.io/tech-knowledge-garden/news/2e297cf400e7d42e)

발표 2026-06-23

연구·기술 · 연구 소개 · Hugging Face

Hugging Face 블로그는 2026년 6월 23일(한국시간), Transformers.js에서 Cross-Origin Storage 제안을 시험하는 방법을 소개했다. 서로 다른 웹사이트가 같은 모델·WebAssembly 파일을 반복 저장하는 문제를 줄이기 위해, 파일의 암호학적 해시를 키로 사용하는 공유 저장소를 제안한다.

###### 저장 시 검증과 공개 범위

파일을 쓸 때 선언한 해시와 실제 내용이 일치해야 저장된다. origins 설정은 전역 공개, 지정한 사이트 목록, 기본값인 같은 사이트 범위를 구분하며, API는 URL 대신 해시로 파일을 찾는다.

###### 선택적으로 켜는 실험 경로

글에서 소개한 API는 아직 브라우저에 기본 구현되지 않은 초기 제안이다. 확장 프로그램의 polyfill과 Transformers.js의 experimental\_useCrossOriginStorage 설정으로 시험하며, API가 없으면 기본 Cache API 경로를 사용한다.

공유 파일이 이용자의 방문 기록을 드러내지 않도록, 브라우저가 파일 존재 확인을 제한하는 방식을 제안한다. 저장소 조회 오류가 나면 앱은 네트워크 다운로드로 돌아가도록 설명했다.

#### [코딩 에이전트 탐지 연구, 저장소 파일·커밋·계정 신호를 함께 대조](https://skyan0213.github.io/tech-knowledge-garden/news/99963ac111426254)

발표 2026-06-23

연구·기술 · 연구 소개

연구진은 2026년 6월 23일 arXiv에, 1억8천만 개 이상 Git 저장소에서 AI 코딩 에이전트의 흔적을 여러 방식으로 탐지하는 사전공개 논문을 제출했다. v1 초록은 설정 파일·커밋 메시지·작성자 식별·봇 서명을 결합하고 탐지 유형에 따라 활동을 분류했다고 설명한다.

##### 한 가지 신호로 찾은 커밋의 비율

한 스냅샷에서 여러 탐지 방법으로 찾은 Claude Code 커밋은 850,157개였고, 봇 계정 조회로 회수한 것은 28,154개(3.3%)였다. 이는 해당 표본에서 탐지 방식별 회수량을 비교한 수치다.

연구진은 탐지 패턴을 495개 수작업 라벨로 검증했다. PR 조사와 커밋 탐지가 서로 다른 도입 집단과 작업을 잡아내며, 관찰된 작업 구성은 도구 자체뿐 아니라 배포·탐지 방식에 영향을 받는다고 초록은 설명한다.
