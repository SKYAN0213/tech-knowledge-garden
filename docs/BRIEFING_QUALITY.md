# 읽을 내용이 있는 브리핑

2026-09-14 사용자 요청. 기존 분야·테마·국내외·로봇 제조사·기업 전략·논문·교수 창업 조사와 원문 검증을 유지한다. 이 문서의 날짜 탐색·설명 원칙이 과거의 cutoff 이후만 검색하거나 모든 기사를 2~4문장으로 끝내는 해석보다 우선한다.

## 빠뜨린 사건이 사라지지 않는 조사

1. `npm run context`의 `discovery_window`를 읽는다. 매 실행 최근 7일을 겹쳐 검색하며 실행이 오래 비었으면 마지막 cutoff부터의 더 긴 기간도 포함한다. `publication_after`는 신규 사건의 시간 경계, `discovery_start`는 검색 시작이다. 두 값을 혼동하지 않는다.
2. 고정 목록·원문 URL 목록을 읽었다는 사실은 수록 완료가 아니다. `.local/research/candidate-backlog.json`의 후보와 실제 기사 ID·원문 URL을 비교한다. 기존에 다운로드했거나 검색에서 본 URL도 기사에 없으면 미수록이다.
3. 중요한 미수록 사건은 후보로 남긴다. `research-candidates/v1`의 candidates에 key/title/source_urls/source_published_at/discovered_at/review_status/priority를 기록한다. review_status는 unreviewed/verified/deferred/rejected, priority는 high/normal이다. 보류·제외의 reason은 비공개다. 공식 자료 접근 실패 후보는 다른 언어판·PDF·상대 당사자·독립 취재 경로를 다음 실행에서 재시도한다. 날짜가 지났다고 자동 만료하지 않는다.
4. 선정은 실제 제품 제공, 기술·비용·성능 조건, 고객 현장 도입, 계약·자금·인력·생산 배분, 주요 연구 방법·사업화 사건의 정보 가치로 판단한다. 경미한 기능 변경이 중요한 미수록 발표를 밀어내지 않았는지 대조한다. 점수나 건수로 진실·중요도를 자동 판정하지 않는다.
5. 새로 확인한 과거 사건은 원 발표가 해당하는 **기존 취재 구간의 회차**에 보완한다. 발표일과 실제 검토일을 따로 보존한다. 과거 회차가 없으면 임의의 과거 회차를 만들지 않고 배경·후속 조사로 보관한다. 기존 coverage_start/end·기사 ID·회차 URL·RSS GUID/pubDate를 바꾸지 않는다.
6. 오늘의 맥락에 필요한 과거 사건은 `recent_event_ids`로 참조한다. 검증한 이전 기사 중 발표일이 당일 포함 7개 달력 날짜 안에 있는 것만 허용한다. 웹·RSS·GitHub의 `지난 7일 주요 발표`에 발표일과 동일 기사·원문 링크를 표시한다. 오늘의 new_items_count나 새로운 기사·RSS 회차를 늘리지 않는다. 분야당 최대 5건은 오늘 기사와 이 참조를 합쳐 적용한다. 매일 같은 사건을 반복 선별하지 말고 맥락과 독서 분량을 판단한다.

## 요약과 설명

육하원칙 2~4문장은 **리드**다. 기술 구조, 적용 공정, 비교 수치, 사업 실행을 이해하는 데 설명이 필요한 사건은 원문에서 확인한 내용을 이어 쓴다.

- 제품·기술: 무엇을 입력해 어떤 처리를 하고 무엇이 나오는가. 실제 사용 단계·대상·출시 상태는 무엇인가.
- 기업: 계약·투자·생산·인력이 어디에 배분되는가. 이전 발표와 비교 가능한 변화는 무엇인가.
- 연구: 문제·방법·실험 조건·결과를 구분한다. 전문 열람과 비교 근거 없이 논문 심층으로 분류하지 않는다.
- 용어는 등장 지점에서 짧게 풀어 쓰고 검증된 개념 ID로 연결한다. 매개변수 전체 수와 활성 수, 생산능력 목표와 생산실적처럼 다른 수치의 대상을 구분한다.

`article_records[].explanations`는 `{heading, paragraphs, source_urls}` 배열이다. 구체적인 소제목, 한 개 이상의 문단, 해당 기사에서 읽은 원문을 기록한다. 문단과 `### 소제목`은 기사 본문에도 동일하게 쓴다. 웹 브리핑·RSS·GitHub는 같은 레코드를 출력한다. 뉴스 목록은 짧은 리드, 기사 상세는 전체 본문이다. 내용이 없으면 필드를 생략하며 설명을 채우기 위한 추론은 금지한다.

`briefing_highlights`에는 오늘 기사와 recent_event_ids에서 선정한 사건 ID 3~5개를 순서대로 기록할 수 있다. 주요 소식에서도 원 발표일을 표시한다. 기존 headlines는 해당 회차 자체 기사 목록으로 보존한다.

## 발행 전 직접 읽기

최종 웹과 공유 원고를 읽으며 아래 사항을 비공개 Research에 판정한다. 테스트 통과로 이 판정을 대체하지 않는다.

- 중요한 발견 후보가 실제 기사나 보류 기록 중 어디에 남았는가.
- 제목·리드만으로 누가 무엇을 했는지 알 수 있고, 설명에서 작동·조건·집행 대상 중 필요한 정보를 얻는가.
- 원문의 계획·회사 주장·발표일·수치 조건이 유지되는가.
- 근거 없는 전망, 같은 내용 반복, 기사와 무관한 안내·변명 문구가 없는가.
- 브리핑에서 설명이 실제로 보이고, 모바일 탭·키보드·공유 URL과 원문·기사 링크가 작동하는가.

후보 목록·선정 사유·검토 기록은 기존 Drive Research에 보관한다. 후보 목록이 없으면 context가 missing으로 보고하며, 이를 조사 완료로 바꾸지 않는다. 공개 저장소에 후보와 실패 사유를 커밋하지 않는다. 기존 오전 8시 실행과 Drive → GitHub → WebsiteData 순서를 유지한다.
