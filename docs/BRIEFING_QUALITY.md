# 읽을 내용이 있는 브리핑

2026-09-14 사용자 요청. 기존 분야·테마·국내외·로봇 제조사·기업 전략·논문·교수 창업 조사와 원문 검증을 유지한다. 이 문서의 날짜 탐색·설명 원칙이 과거의 cutoff 이후만 검색하거나 모든 기사를 2~4문장으로 끝내는 해석보다 우선한다.

## 빠뜨린 사건이 사라지지 않는 조사

1. `npm run context`의 `discovery_window`를 읽는다. 매 실행 최근 7일을 겹쳐 검색하며 실행이 오래 비었으면 마지막 cutoff부터의 더 긴 기간도 포함한다. `publication_after`는 신규 사건의 시간 경계, `discovery_start`는 검색 시작이다. 두 값을 혼동하지 않는다.
2. 고정 목록·원문 URL 목록을 읽었다는 사실은 수록 완료가 아니다. `.local/research/candidate-backlog.json`의 후보와 실제 기사 ID·원문 URL을 비교한다. 기존에 다운로드했거나 검색에서 본 URL도 기사에 없으면 미수록이다.
3. 중요한 미수록 사건은 후보로 남긴다. `research-candidates/v1`의 candidates에 key/title/source_urls/source_published_at/discovered_at/review_status/priority를 기록한다. review_status는 unreviewed/verified/deferred/rejected, priority는 high/normal이다. 보류·제외의 reason은 비공개다. 공식 자료 접근 실패 후보는 다른 언어판·PDF·상대 당사자·독립 취재 경로를 다음 실행에서 재시도한다. 날짜가 지났다고 자동 만료하지 않는다.
4. 선정은 실제 제품 제공, 기술·비용·성능 조건, 고객 현장 도입, 계약·자금·인력·생산 배분, 주요 연구 방법·사업화 사건의 정보 가치로 판단한다. 경미한 기능 변경이 중요한 미수록 발표를 밀어내지 않았는지 대조한다. 점수나 건수로 진실·중요도를 자동 판정하지 않는다.
5. 2026-10-12 사용자 요청에 따라 **오늘 후보와 이전 미수록 사건을 함께 경쟁시킨다**. 근거·신규성·현재 유효성을 검토한 과거 미수록 사건은 오늘 브리핑에 처음 소개할 수 있다. 원문 발표일을 오늘로 바꾸지 않고 원 회차·판본·검토일을 보존한다. 최초 소개는 실제 canonical 기사/브리핑 이력으로 확인하며 선정·작성·승인만으로 수록 완료를 표시하지 않는다. 이미 발행한 기사의 정정·보완은 기존 회차·기사 ID·URL·RSS GUID/pubDate를 유지한다. 과거 미수록 사건을 오늘 처음 소개하는 것과 기존 기사 재참조·소급 정정을 구분한다.
6. 오늘의 맥락에 필요한 과거 사건은 `recent_event_ids`로 참조한다. 검증한 이전 기사 중 발표일이 당일 포함 7개 달력 날짜 안에 있는 것만 허용한다. 웹·RSS·GitHub의 `지난 7일 주요 발표`에 발표일과 동일 기사·원문 링크를 표시한다. 오늘의 new_items_count나 새로운 기사·RSS 회차를 늘리지 않는다. 분야당 최대 5건은 오늘 기사와 이 참조를 합쳐 적용한다. 매일 같은 사건을 반복 선별하지 말고 맥락과 독서 분량을 판단한다.

## 작성 전 큐레이션 (2026-10-12)

`classification.review → curation.prepare/evaluate/select → selection.prepare`를 사용한다. 큐레이션은 사건·원문 저장소를 복제하지 않고 검토된 사건 계획의 참조만 대기 큐에 보존한다. 수집/분류를 완료한 사건 중 선정된 사건에만 이후 근거 추출·기사 작성을 적용한다.

필수 조건은 원문 근거, 조사 범위, 이미 수록한 내용과의 실질적인 차이, 현재 유효성, 검색된 기존 기사 전체와의 대조다. 제품명·회사·날짜만 바뀐 반복, 홍보 문구, 근거 없는 시장 효과는 점수로 통과시킬 수 없다. 후속 변화·정정은 기존 사건 관계 검토를 사용한다.

| 평가 항목 | 비중 | 점수의 근거 |
|---|---:|---|
| 신규성 | 30 | 기존 기사에 없던 사실·조건·실행 단계 |
| 영향 | 25 | 확인된 이용 대상·고객 도입·자원 배분·보안/규제 변화. 기업 인지도나 추정 매출 제외 |
| 구체성 | 20 | 누가·무엇을·언제 했는지와 적용 조건·비교 대상·규모 |
| 지식 가치 | 15 | 작동 원리·연구 방법·사업 실행·변화 이력을 이해하는 정보 |
| 시의성 | 10 | 현재 사용할 수 있는 정보·남아 있는 일정·긴급성. 오늘 발표 가점 제외 |

각 항목은0~5의 정수와 비공개 근거 문장을 기록한다. 가중 점수는100점 만점이고 최소70점, 우선85점이다. 이 값들은 `data/research-curation-policy.json`에서 관리한다. 분야당 최대5·전체 최대40 안에서 높은 점수부터 선별하며 분야 비율·기사 수를 채우지 않는다. 원문 근거 없는 항목을 추론해 점수를 높이지 않는다.

모델 점수는 미검토 제안이다. Codex 등 큐레이터의 원문·이력 대조를 별도 기록한 후 사용하며 사실/기사 승인을 대신하지 않는다. 더 오래됐다는 이유로 자동 감점·만료·삭제하지 않는다. 명시된 효력 기한, 원문 판본, 관련 기사 이력, 정책이 바뀌면 새 풀에서 재검토한다. 변하지 않은 평가·완료 원고는 재사용한다. 점수·보류 이유·운영 상태는 독자 본문에 출력하지 않는다.

## 요약과 설명

새 큐레이션 원고는 검증 사실의 전체 범위를 `validation.completeness`로 읽고 중요/배경 여부와 이유를 원문·사실 SHA에 고정한다. 중요 사실의 수치·비교 조건·제공 대상·계획/완료·회사 귀속 중 필요한 항목을 초안에 남긴다. 리드로 줄이면서 중요한 조건을 제거하지 않는다. 원문의 모든 문장을 옮기는 기준은 아니며 배경·다른 출처의 같은 사실은 명시적으로 구분한다.

최종 `coverage_reviews`는 중요한 사실마다 전달한 문장 위치·문장 SHA·필요한 조건·의미 대조를 기록한다. 참조 ID가 있다는 것만으로 충분하다고 판정하지 않는다. 정확한 누락/변조는 작성·승인에서 차단하며 의미 판단은 원문을 직접 읽은 검토를 따른다. 기존 완료 원고/승인은 당시 판본으로 재사용한다. 검토 상태·누락 사유는 독자 본문에 출력하지 않는다.

브리핑 구성은 개별 중요도 점수를 유지한다. 같은 우선순위에서3점 이내 후보를 비교해 기업/주제의 반복을 줄이고, 원문으로 검토한 추가 정보가 모두 이미 선택한 사건에 포함됐다면 보류한다. 기업명이 같다는 이유로 같은 사건으로 합치거나 중요 사건보다 낮은 점수의 분야를 할당량으로 채우지 않는다. 구성 프로필은 `data/research-briefing-composition-policy.json`과 명시적인 원문 인용을 따른다.

육하원칙 2~4문장은 **리드**다. 기술 구조, 적용 공정, 비교 수치, 사업 실행을 이해하는 데 설명이 필요한 사건은 원문에서 확인한 내용을 이어 쓴다.

- 제품·기술: 무엇을 입력해 어떤 처리를 하고 무엇이 나오는가. 실제 사용 단계·대상·출시 상태는 무엇인가.
- 기업: 계약·투자·생산·인력이 어디에 배분되는가. 이전 발표와 비교 가능한 변화는 무엇인가.
- 연구: 문제·방법·실험 조건·결과를 구분한다. 전문 열람과 비교 근거 없이 논문 심층으로 분류하지 않는다.
- 용어는 등장 지점에서 짧게 풀어 쓰고 검증된 개념 ID로 연결한다. 매개변수 전체 수와 활성 수, 생산능력 목표와 생산실적처럼 다른 수치의 대상을 구분한다.

`article_records[].explanations`는 `{heading, paragraphs, source_urls}` 배열이다. 구체적인 소제목, 한 개 이상의 문단, 해당 기사에서 읽은 원문을 기록한다. 문단과 `### 소제목`은 기사 본문에도 동일하게 쓴다. 웹 브리핑·RSS·GitHub는 같은 레코드를 출력한다. 뉴스 목록은 짧은 리드, 기사 상세는 전체 본문이다. 내용이 없으면 필드를 생략하며 설명을 채우기 위한 추론은 금지한다.

`briefing_highlights`에는 오늘 기사와 recent_event_ids에서 선정한 사건 ID 3~5개를 순서대로 기록할 수 있다. 주요 소식에서도 원 발표일을 표시한다. 기존 headlines는 해당 회차 자체 기사 목록으로 보존한다.

## 발행 전 직접 읽기

최종 웹과 공유 원고를 읽으며 아래 사항을 비공개 Research에 판정한다. 테스트 통과로 이 판정을 대체하지 않는다.

- 중요한 발견 후보가 실제 기사나 보류 기록 중 어디에 남았는가.
- 제목·리드만으로 누가 무엇을 했는지 알 수 있고, 설명에서 작동·조건·집행 대상 중 필요한 정보를 얻는가.
- 원문의 계획·회사 주장·발표일·수치 조건이 유지되는가.
- 가상 고객·기업 시나리오의 도입·시간·비용을 실제 고객 성과로 표현하지 않는가. 사례가 필요한 경우 가상이라는 조건을 본문에 유지하고, 정보 가치가 없으면 생략한다. 실제 연구에서 측정한 시뮬레이션 실험과 가상 고객 시나리오를 구분한다.
- 사람·조직·세션·워크숍의 명시 수치는 해당 문단에서 참조한 검토 사실의 진술과 수치 정보로 확인한다. 인용문에만 있는 숫자나 다른 문단의 사실을 끌어오지 않는다. 자동 수치 검사는 단위·값을 대조하며 회사 귀속·계획/완료·비교 조건의 원문 검토를 대체하지 않는다.
- 근거 없는 전망, 같은 내용 반복, 기사와 무관한 안내·변명 문구가 없는가.
- 브리핑에서 설명이 실제로 보이고, 모바일 탭·키보드·공유 URL과 원문·기사 링크가 작동하는가.

후보 목록·선정 사유·검토 기록은 기존 Drive Research에 보관한다. 후보 목록이 없으면 context가 missing으로 보고하며, 이를 조사 완료로 바꾸지 않는다. 공개 저장소에 후보와 실패 사유를 커밋하지 않는다. 기존 오전 8시 실행과 Drive → GitHub → WebsiteData 순서를 유지한다.

## 로컬 원고의 편집 검사

`node scripts/research.mjs editorial-check --run <원고-run>`은 저장 원문의 무결성과 사실 검토·모델 원출력·명시적 정정 이력을 확인하고 원출력/현재 원고의 분량·날짜·반복을 비공개 JSON으로 돌려준다. 모델 호출·원고 수정·승인은 하지 않는다. 배열 항목 수가 아니라 본문 문장 수2~4와 리드900자를 확인한다. 알려진 날짜가 리드에 없는 경우와 정확히 반복된 문장은 새 승인을 차단한다.

리드와 설명이 같은 사실 ID를 쓰는 것은 중복의 확정 판정이 아니다. 설명에 필요한 작동·조건·세부 사항이 추가되는지 직접 읽고 승인 입력에 `reader_quality_review: {"repetition_checked": true}`를 기록한다. 이 표시만으로 분량·날짜·정확한 반복 오류를 면제할 수 없다. 새 `approve`는 해당 검사와 처리 원고의 정정 chain을 확인하며 비공개 editorial-quality 영수증을 남긴다. 기존 승인 재개는 기존 불변 결정을 그대로 읽는다. 문장 분할·날짜 표기 검사는 의미·원문 사실·회사 귀속·정보 가치 검토를 대체하지 않는다.

공통 `validateEvidence`는 원문에 명시된 ‘다음 사례는 가상 조직’ 범위를 제목 깊이로 추적한다. 하위 제목의 사례는 같은 범위에 남고 동일·상위 제목에서 끝난다. 이 범위의 근거를 쓰면서 사실 진술에서 가상 조건을 빠뜨리면 `fictional_scenario_presented_as_observed`로 사실 승인을 차단한다. 회사 발언으로 귀속해도 실제 성과로 바꿀 수 없다. 이 구조 검사는 알려진 명시 표현의 누락을 잡으며, 원문 전체의 의미 검토를 대체하지 않는다.

한국어 종결 뒤 `npm`, `api`처럼 소문자로 시작하는 기술 명칭이 이어져도 독립 문장으로 센다. Unicode 분할기의 약어 판단이 실제 두 문장을 하나로 합치지 않도록 보완하되 숫자·버전·URL과 인용 뒤 `라고/고` 연결은 유지한다. 이 경우에도 과도한 리드 분량이나 설명의 반복 문장을 승인하지 않는다.
