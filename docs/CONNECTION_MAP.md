# 연결 지도

사진의 작은 점·가는 선·어두운 배경을 실제 개념, 키워드, 뉴스로 구현한다. 관계를 화살표나 참조 유형으로 한정하지 않는다. 확인한 연관성만 있어도 연결하며, 관계가 없는 노드를 시각적 밀도를 높이기 위해 추가하지 않는다.

## 엔진

[Sigma.js 3](https://www.sigmajs.org/)의 WebGL 렌더러와 [Graphology ForceAtlas2](https://graphology.github.io/standard-library/layout-forceatlas2.html)를 사용한다. 연결의 가중치·반발력·노드 크기를 고려해 배치하고 Louvain 커뮤니티를 색으로 구분한다. 모두 MIT 라이선스이며 외부 서비스 호출이나 이용료가 없다.

| 후보                                                           | 적합한 용도                            | 이번 선택                                                                         |
| -------------------------------------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------- |
| Sigma.js + ForceAtlas2                                         | 많은 작은 점과 연결을 탐색하는 2D 지도 | 채택. 뉴스 목록과 함께 읽기 좋고 WebGL을 사용한다.                                |
| [3d-force-graph](https://github.com/vasturiano/3d-force-graph) | 회전 가능한 3D 네트워크                | 실제 3D가 필요할 때의 대안. 현재는 깊이와 가려짐 없이 읽을 수 있는 2D를 사용한다. |
| [Cytoscape.js](https://js.cytoscape.org/)                      | 복잡한 노드 스타일과 그래프 편집·분석  | 편집기 중심 요구가 생겼을 때 검토한다.                                            |

빌드할 때 결정적인 초기 좌표를 저장한다. 브라우저의 ‘다시 배치’는 별도 Web Worker에서 600회 계산하므로 읽기와 입력 처리를 가로막지 않는다. WebGL이 없으면 노드 목록·검색·관련 뉴스로 전환한다. Worker 실행이 실패하면 기존 지도를 유지한다. 축적량이 늘면 먼저 실제 데이터로 측정하며, 큰 그래프의 성능을 현재 166개 노드 검증에서 추정하지 않는다.

## 연결 데이터

개념의 고정 `concept_id`, 원문으로 정리한 `keywords`, 기사에 지정한 개념, 본문에 실제 등장하는 키워드가 재료다. `news-connections/v2`는 세 종류의 노드와 다음 무방향 연결을 만든다.

- 확인된 개념 간 연관 관계.
- 개념과 그 개념에 저장된 키워드.
- 뉴스와 편집자가 지정한 개념.
- 뉴스와 제목·요약·실제 본문에 등장하는 기존 키워드. 안내 문구, 섹션 제목, 출처 목록은 제외한다.

한글 정규화와 영문 단어 경계를 적용한다. 이름·별칭에 해당하는 키워드는 기존 개념으로 합친다. 같은 두 노드 사이의 선은 하나이고 여러 연결 이유를 보존한다. 기사와 키워드의 연결은 주제상 연관성이다. 인과관계, 기술 의존성 또는 기사 사실의 재검증을 뜻하지 않는다.

새 개념 간 연결에는 대상 ID와 확인한 이유만 있으면 된다.

```yaml
connections:
  - target: mcp
    reason: 에이전트가 외부 도구를 연결할 때 함께 사용하는 기술이다.
```

원문 URL이 있으면 `evidence: [https://...]`를 추가한다. 방향, 관계 유형, 인용은 필수가 아니다. 추측으로 빈 관계를 채우지 않는다. 기존 `relations`에 저장된 유형·원문·분석 구분은 손실 없이 유지하며 웹에서는 동일한 무방향 연결로 표현한다. 정의·키워드의 원문 확인 규칙은 유지한다.

Obsidian의 `관련 개념`에는 같은 연결을 `- [[Knowledge/…|개념]] — 확인한 이유`로 적는다. 확인된 연결이 없으면 `없음`으로 둔다. `npm run refresh`가 개념 간 관계 표를 Obsidian 지도에 반영한다. 키워드를 위한 빈 노트는 만들지 않으며, 웹에서만 키워드·뉴스 노드를 더해 확장한다.

## 노드와 뉴스

선택한 노드에서 최대 두 번의 연결로 닿는 뉴스만 표시한다. 직접 지정한 개념의 기사를 먼저, 연관 개념과 공유 키워드를 통한 기사를 뒤에 둔다. 같은 순위에서는 최신 기사가 먼저다. 간접 연결에는 거친 개념·키워드를 표시한다. 기사 노드를 선택하면 그 기사와 관련 기사들을 보여 준다.

홈과 기사·개념 페이지에 지도를 넣고 상단 메뉴에서 전체 지도를 열 수 있다. 선택 상태는 전체 지도 주소의 `?focus=`에 담겨 공유할 수 있다. 검색, 노드 선택, 인접 연결 보기, 이동, 확대, 드래그, 맞춤과 다시 배치를 지원한다. 키보드 검색·노드 목록은 작은 점을 누르기 어려울 때도 사용 가능하다.

## 검증

```sh
npm test
npx tsc --noEmit
npm run build
node scripts/verify-site.mjs
node scripts/benchmark-connections.mjs
```

벤치마크는 현재 데이터와 합성 노드 1,000개·연결 2,200개의 **배치 계산만** 측정한다. 합성 자료는 출력 화면에 추가하지 않는다. 실제 브라우저의 프레임 속도나 휴대폰 성능을 측정한 결과로 해석하지 않는다. 배포 전에는 실제 브라우저에서 노드 선택 → 뉴스 열기, 검색, 드래그, 재배치, 모바일 너비, WebGL 비활성 환경의 목록 동작을 확인한다.
