# 연결 지도

IT·AI·로봇 뉴스를 읽으며 뜻과 작동 원리를 배울 필요가 있는 **전문 용어**를 연결한다. 일반 단어를 많이 모으는 지도가 아니다. 기사 제목은 노드로 만들지 않으며, 용어를 선택하면 관련 뉴스를 표시한다.

## 노드 선정

GPT가 원문을 읽고 다음 조건을 모두 확인한 용어만 포함한다.

1. 일반 독자가 기사 이해를 위해 별도 설명을 필요로 하는 기술 용어다. 구체적인 메커니즘, 프로토콜, 모델 구조, 평가 방법, 측정 개념 또는 보안 원리여야 한다.
2. 무엇인지, 어떻게 작동하는지, 무엇과 혼동하기 쉬운지를 독립적으로 설명할 수 있다.
3. 실제로 읽은 일차 자료, 한 문장 정의, 완성된 설명 노트가 있다.
4. 왜 이 용어를 배워야 하는지 구체적인 선정 이유를 남긴다.

빈도, 긴 이름, 영문 표기, 약어라는 이유만으로 포함하지 않는다. 책임·상태·가격·허용·근거 같은 일반어, 응용 분야나 사업 주제만 묶은 넓은 분류, 제품·회사·기사 제목은 노드로 만들지 않는다. `keywords`는 노트와 사이트 검색의 보조 정보이며 지도 노드나 기사 연결을 자동 생성하는 재료가 아니다. `aliases`에는 같은 용어의 정확한 이름·약어만 넣고 일반 연관어를 넣지 않는다.

선정 결과는 각 canonical concept의 frontmatter에 기록한다.

```yaml
map_review:
  decision: include
  kind: mechanism
  reason: 문맥이 길어질 때 추론 메모리와 속도가 달라지는 이유를 키·값 재사용으로 설명하는 기술이다.
  reviewed: 2026-09-13
```

`kind`는 `mechanism`, `protocol`, `architecture`, `model`, `evaluation`, `metric`, `security` 중 하나다. 제외할 때는 `decision: exclude`와 구체적인 이유·검토일을 기록한다. 미검토 노트는 자동으로 포함하지 않는다. 포함 결정에 정의·설명 경로·출처·선정 이유가 빠지면 검사가 실패한다. 이 검사는 구조를 확인하며 용어의 학습 가치는 GPT의 원문 검토로 판단한다. 사용자의 노트별 공개 승인 절차가 아니다. 선정 이유와 검토 기록은 내부 노트에 유지하고 공개 graph에는 정의·분류·출처만 투영한다. 제외된 문서와 기존 링크는 읽을 수 있다.

2026-09-13 검토 결과는 [선정 기록](../data/graph-node-review-2026-09-13.json)에 있다. 기존 23개 문서 중 12개를 포함하고 넓은 주제 11개는 지도에서 제외했다. 실제 기사에 필요한 KV 캐시, OIDC, 제로샷 추론, p95·p99 지연을 원문으로 설명한 독립 노트 4개를 추가했다. 현재 노드는 16개, 확인된 연결은 17개다. 숫자를 맞추는 목표나 상한은 없으며 적합한 새 용어가 축적되면 늘어난다.

## 연결과 기사

`learning-connections/v4`는 선정된 전문 용어만 노드로 제공한다. 개념 사이의 선은 양쪽 모두 선정된 용어 사이의 **확인된 무방향 연관성**이다. 같은 쌍의 선은 하나로 합치고 여러 확인 이유는 보존한다. 제외된 중간 노드를 제거하면서 이웃을 임의로 이어 붙이지 않는다. 공동 등장만으로 선을 만들지 않는다.

```yaml
connections:
  - target: inference
    reason: 모델 서빙에서 이전 토큰의 어텐션 키·값을 재사용해 반복 계산을 줄인다.
```

연관성이 확인되면 충분하며 방향·참조 유형·인용은 필수가 아니다. 원문이 있으면 `evidence: [https://...]`를 추가한다. 기존 `relations`의 유형·근거·source/inference 구분은 원본에서 보존한다. Obsidian 본문에는 `- [[Knowledge/…|용어]] — 확인한 이유`를 적고, 연결이 없으면 `없음`으로 둔다. `npm run refresh`가 같은 선정 기준으로 Obsidian 지도의 용어 목록과 관계 표를 만든다.

뉴스는 별도 `articles` 데이터다. 기사와 개념의 의미 연결은 전체 공개 기사와 원문 근거를 대조한 `knowledge.semantic_*` workflow가 만든 해시 고정 색인(`data/article-semantic-review-index.json`)에서 읽는다. 기사는 정확히 일치하는 native 승인과 검증된 공개 사실이 있어야 검토할 수 있다. 승인·원문·공개 문장·개념 노트·모델 정책이 달라지면 이전 결과를 재사용하지 않는다. 확정 연결에는 `topic`, `application`, `comparison_evaluation`, `context_background` 역할과 공개 문장에 실제 사용된 검증 claim이 붙는다. 결과는 전체 검토를 마친 `reviewed_links` 또는 명시적으로 연결이 없는 `reviewed_none`이며, 모델이 제안한 간접 관계와 새 용어는 후보로 남아 지도 선을 만들지 않는다.

검토 결과가 없는 기존 기사도 뉴스 목록에서는 계속 읽을 수 있다. 기존 native 검토에 지정된 개념은 `untyped`로 구분해 유지하지만, 제목·본문의 단어 일치만으로 연결을 만들지 않는다. 신규 전체 검토는 누락된 모든 기사를 대기열에 올리고 승인·저장 불일치가 있는 기사를 차단한다. 새 일일 workflow는 기사·원문 승인·개념 판본·모델 정책 지문이 그대로인 이전 영수증만 재사용해 새 기사와 변경된 기사만 추가 검토한다.

전체 개념 설명을 매 기사 요청에 반복하지 않도록 검토된 개념 전용 혼합 색인을 쓴다. 정확한 정식 이름·별칭은 모두 후보에 남기고, BM25형 어휘 역색인과 `qwen3-embedding:8b` 벡터 순위를 reciprocal-rank fusion으로 합쳐 상위 12개를 찾는다. 축약 전에는 동일 색인·정책·모델 digest에서 본 기사 최소 24개(4개 분야군에서 각각 2개 이상)와 별도 모호함·동음이의어·연결 없음 8개를 실제 검토한다. v3 평가는 엄격한 `recall@12 ≥ 95%`와 실제 개념 입력 bytes 중앙값 60% 이상 절감을 함께 요구한다. 정답은 검증된 native 전문 개념 승인 또는 full-registry Luna 영수증과 원문 블록 대조를 포함한 별도 검토에서만 읽으며 승인·검토 원본 SHA를 매번 다시 대조한다. 이 조건을 충족하지 못하면 전체 registry로 되돌린다. 임베딩은 검색 후보를 고르는 데만 쓰며 Luna가 대상 기사·검증 주장·선택 후보를 원문과 대조해 관계를 판단한다. 인덱싱·후보 고정·무효화·복구 기준은 [기사 의미 후보 검색](SEMANTIC_CANDIDATE_RETRIEVAL.md)에 있다.

개념 노트 `keywords`와 기사 응답의 `keyword_candidates`는 서로 다른 검색 메타데이터다. 별칭은 같은 개념의 정확한 다른 이름만 담는다. 기사 키워드 후보는 공개 검증 주장 ID가 연결된 비공개 검토 receipt에만 남고 공개 의미 연결 index에는 내보내지 않는다. 키워드·태그만으로 관계, 별칭 또는 지도 노드를 생성하지 않는다.

기존 기사 한 편의 의미를 처음부터 검토할 때는 다음 모듈 순서를 사용한다. `semantic_prepare`가 최신 공개 기사와 승인 원문을 고정하고, 각 `waiting_for_reasoning` 작업은 exact `task_id`와 `request_sha256`에 바인딩된다. 연결 담당자는 페이지를 끝까지 읽어 정확한 요청을 구독형 `gpt-6-luna`에 전달한 뒤 `reasoning.submit`으로 결과를 넣는다. 제출 단계에서 요청의 사건 ID, 공개 검증 주장 ID, 검토된 개념 ID, 관계 중복 및 결과 상태를 대조해 잘못 묶인 응답이 불변 결과로 저장되는 것을 막는다. 과거 결과가 사건 ID나 공개 claim 참조 검증에 실패하면 `semantic_retry`가 같은 고정 입력으로 새 task를 만들고 이전 결과를 보존한다. 이 새 task도 정확한 Luna 결과 제출이 필요하다. `semantic_resume`은 결과와 claim 참조를 다시 검증해 영수증으로 고정하고, `semantic_export`는 모든 공개 기사가 완료된 경우에만 색인을 원자적으로 갱신한다. 개발 완료 gate가 닫혀 있거나 원문 승인·저장·검토가 불완전하면 준비·내보내기를 거부한다. 이 workflow는 사실/편집/기사/release 승인을 만들지 않고 Drive 저장이나 배포를 수행하지 않는다.

색인을 쓴 뒤에는 다음 순서로 표시한다.

1. 원문 근거와 연결 역할을 검토한 의미 연결.
2. 기존 native 승인에 남아 있는 정확한 개념 ID 지정(`untyped`).
3. 확인된 개념 선 하나로 연결된 이웃 용어의 기사. 경유 용어를 표시함.

같은 순위에서는 최신 기사가 먼저다. 의미 역할은 주제, 적용, 비교·평가, 배경 순으로 표시하며 오래된 `untyped` 지정은 의미 검토 결과보다 뒤에 둔다. 마지막 단계에서 다시 이웃을 따라 확장하지 않는다. 이름·별칭의 본문 출현은 검색을 도울 뿐 기사 관계를 생성하지 않는다. 지도 연결은 검토된 주제 관계이며 인과관계나 과거 기사 사실의 재검증을 뜻하지 않는다. 현재 전체 기사의 의미 검토 색인은 아직 운영 gate를 통과해 생성되지 않았으므로, 기존 연결 비율을 검토 완료 수치로 표시하지 않는다.

상단 메뉴의 전용 페이지에서 전체 지도를 볼 수 있다. 관련 전문 개념 페이지는 선정 용어가 있을 때 해당 용어에 초점을 둔 지도를 표시한다. 뉴스 홈·목록·상세와 브리핑에는 지도를 넣지 않는다. 선택 상태는 `?focus=`로 공유한다. 이전 기사 초점 주소는 해당 기사의 첫 선정 용어로, 이전 키워드 주소는 일치하는 선정 용어로 연결한다. 일반어·제외 항목의 옛 초점은 해제한다.

## 엔진과 조작

[Sigma.js 3](https://www.sigmajs.org/)의 WebGL, [Graphology ForceAtlas2](https://graphology.github.io/standard-library/layout-forceatlas2.html)의 자동 배치, Louvain 커뮤니티 색상을 유지한다. 연결 가중치·반발력·노드 크기를 고려해 작은 점과 가는 선을 배치한다. 모두 MIT 라이선스이며 외부 서비스 호출이나 이용료가 없다.

| 엔진                                                           | 적합한 용도             | 선택                                     |
| -------------------------------------------------------------- | ----------------------- | ---------------------------------------- |
| Sigma.js + ForceAtlas2                                         | 연결을 탐색하는 2D 지도 | 사용 중                                  |
| [3d-force-graph](https://github.com/vasturiano/3d-force-graph) | 회전 가능한 3D 네트워크 | 깊이·가려짐이 필요한 요구가 생길 때 검토 |
| [Cytoscape.js](https://js.cytoscape.org/)                      | 그래프 편집·분석        | 편집기 요구가 생길 때 검토               |

검색·용어 목록·연결 필터·이동·확대·드래그·맞춤을 지원한다. 다시 배치는 Web Worker에서 600회 계산한다. WebGL이 없으면 검색·용어 목록·관련 뉴스로 전환하며, Worker 실패 시 현재 지도를 유지한다. 노드 수를 시각적 밀도를 위해 부풀리지 않는다.

## 검증

```sh
npm test
npx tsc --noEmit
npm run build
node scripts/verify-site.mjs
```

일반 키워드의 자동 유입 방지, 포함 결정의 필수 정보, 실제 별칭 매칭, 제외 노드의 연결 우회 방지, 기사 순위와 탐색 범위, 이전 초점 주소, 문서·문단 링크와 RSS를 검사한다. 브라우저에서는 일반어 검색 결과 없음, 전문 용어 선택 → 정의·관련 기사 → 기사 열기, 뉴스·브리핑의 지도 없음과 전문 개념 지도, 재배치, 모바일 너비와 그래픽 미지원 목록을 확인한다.

`node scripts/benchmark-connections.mjs`는 현재 데이터와 합성 노드 1,000개·연결 2,200개의 배치 계산만 측정한다. 합성 자료는 공개 화면에 추가하지 않으며 결과를 실제 휴대폰 성능으로 해석하지 않는다.
