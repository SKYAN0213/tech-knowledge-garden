# 분야와 테마로 조사하기

2026-09-13 사용자 승인. 다음 정기 회차인 2026-09-14부터 적용한다. 기존 8개 분야는 `SECTOR_BRIEFING.md`를 따른다. 분야는 어느 산업인지, 테마는 무엇이 달라졌는지를 나타낸다. GPT가 원문을 읽고 분류하며 코드가 형식·중복·전달을 검증한다. 추가 유료 API나 예약은 만들지 않는다.

## 매일 두 조사 경로 확인

8개 분야 각각에서 아래 두 경로를 모두 확인한다. 모든 테마마다 기사를 채우거나 기술·기업 기사를 절반씩 강제하지 않는다. 분야당 총 최대 5건, 총 최대 40건이며 커버 기사도 포함한다.

| 경로 | 조사할 자료와 변화 |
| --- | --- |
| 기술·제품 | 논문, 기술 문서, 공식 개발 기록, 제품 발표, 실증·재현, 성능·비용, 표준·라이선스 |
| 기업·운영 | 기업 IR·실적 발표, 공시, 투자·인수합병·계약, 채용·감원·핵심 인재 이동·조직 개편, 설비·양산·공급망, 관련 규제·사고 |

기업 발표가 기술 검색에서 우연히 잡히는 것에 의존하지 않는다. 분야별 주요 기업과 해당 기간 새 사건의 당사자를 대상으로 기업·운영 경로를 별도 조사한다. 기업 공식 발표·IR, [DART](https://dart.fss.or.kr/), [SEC EDGAR](https://www.sec.gov/edgar/search/) 및 해당 국가 공시·감독기관의 원문을 우선한다. 비상장 기업은 공식 회사·투자자 발표와 허용된 독립 보도를 확인한다. 기술·사업 역량이나 재무 상태를 실질적으로 바꾸는 사건을 우선하며, 소문·반복 홍보·근거 없는 인력 추정으로 채우지 않는다.

`.local/research/YYYY-MM-DD.md`에 `분야 × 기술·제품/기업·운영`의 **16개 확인 행**을 남긴다. 각 행에는 실제 확인한 채널·원문 URL·확인 시각·게시 시각 근거·선정 사건 ID 또는 제외 이유·접근 실패를 적는다. 상태는 `확인`, `부분 확인`, `접근 실패`로 구분한다. 아무 조사도 못 했다면 `미실시`와 이유를 남기고 조사 완료로 보고하지 않는다. 확인한 뒤 새 사건 0건인 것과 접근 실패는 다르다. 기록은 기존 Drive Research 보관 절차로 저장한다. 작성 예시는 `templates/research-coverage.md`를 사용한다.

## 테마와 세부 태그

정확한 이름은 아래 표와 `scripts/themes.mjs`를 함께 유지한다. 임의의 유사 태그를 계속 만들지 않는다.

| 주/보조 테마 | 세부 태그 |
| --- | --- |
| 연구·기술 | 새로운 방법, 성능 개선, 비용 절감, 실증·재현 |
| 제품·서비스 | 신제품, 기능 추가, 가격 변경, 서비스 종료 |
| 사업·고객 | 고객 도입, 수주·계약, 시장 진출, 사업 철수 |
| 실적·재무 | 매출, 수익성, 현금흐름, 부채, 실적 전망 |
| 투자·기업거래 | 투자 유치, 지분 투자, 인수합병, 사업 매각 |
| 인력·조직 | 채용 확대, 인력 감축, 핵심 인재 이동, 조직 개편, 경영진 교체 |
| 생산·공급망 | 설비 투자, 증설, 양산, 공급 부족, 조달 변경 |
| 표준·생태계 | 기술 제휴, 표준 채택, 호환성, 오픈소스, 라이선스 |
| 정책·규제 | 인허가, 보조금, 수출 통제, 반독점, 법률 변경 |
| 위험·사고 | 보안 사고, 서비스 장애, 리콜, 안전 문제 |

- 기사마다 주 분야 1개, 주 테마 1개, 보조 테마 최대 1개, 해당 테마의 세부 태그 1~3개를 기록한다. 보조 테마가 없으면 `없음`이다. 주/보조 테마는 서로 달라야 한다.
- 같은 사건은 여러 테마에 해당해도 한 번만 수록한다. 주 테마는 사건의 직접적인 변화, 보조 테마는 원문에 확인된 부수적인 변화다. 예상 효과만으로 보조 태그를 붙이지 않는다.
- 투자 유치·지분 거래는 `투자·기업거래`, 실적·현금흐름은 `실적·재무`, 설비 투자·증설은 `생산·공급망`이다. 공급 계약은 수주가 핵심이면 `사업·고객`, 조달 변경이 핵심이면 `생산·공급망`이다. 표준·호환성 협력은 `표준·생태계`다.
- 분야는 영향을 받는 기술·사업을 기준으로 정한다. 여러 사업을 가진 회사의 전사 사건은 본문에 전사 범위를 명시하고 근거가 가장 직접적인 주 분야 한 곳에만 싣는다. 부문 수치가 없으면 전사 실적을 특정 기술의 성과로 해석하지 않는다.
- 기업·기관은 별도 이름 목록이다. 기존 `npm run context`의 이름을 재사용하고, 자회사·모회사와 계약 당사자를 구분한다. 분류에 필요한 실제 당사자만 적으며 없으면 `없음`이다.
- 계획·계약·승인·실제 집행·완료를 본문에서 구분한다. 투자 계획은 집행액이 아니며 채용 공고는 실제 순인원 증가가 아니다. 회사의 원인 설명과 독립적으로 확인한 사실도 구분한다. 수치는 기간·통화·단위·비교 기준을 함께 적는다.
- 테마·기업·세부 태그는 탐색용이다. 연결지도 노드나 용어 별칭, 개념 연관성으로 자동 변환하지 않는다.

## 원고 형식

새 회차 frontmatter에 두 필드를 모두 쓴다.

```yaml
briefing_format: sector-five/v1
theme_format: news-themes/v1
```

커버·뉴스·논문·도구의 **모든 기사**에 제목 다음의 메타데이터를 넣는다. 여러 세부 태그와 기업명은 쉼표로 구분한다. 아래는 형식 설명용 예시이며 실제 취재 기사로 저장하지 않는다.

```markdown
## 확인한 사건의 구체적인 제목

**분야:** 로봇·제조
**테마:** 투자·기업거래
**보조 테마:** 없음
**세부 태그:** 투자 유치
**기업·기관:** 실제 발표 당사자

**핵심:** 원문에서 확인한 변화와 수치. [S1]

**의미:** 편집 분석임을 구분한 의미.

**확인할 점:** 계획/완료 여부, 제한 또는 다음 확인할 지표.
```

기존 v2 기사 구조·출처·사실/분석 분리 규칙도 따른다. 2026-09-14 이후 회차의 테마 형식 누락, 잘못된 분류, 누락/반복 필드, 태그 초과는 생성·검증을 중단한다. 이전 회차에는 태그를 추정해서 붙이지 않는다. 검증된 새 사건이 없으면 기존 빈 회차 규칙을 지키고 기사나 분류를 만들어 넣지 않는다.

`refresh`는 News의 구조화된 메타데이터와 Obsidian `tags`를 생성한다. 웹 뉴스에서 분야·테마·기업 필터를 조합하고 URL로 공유할 수 있다. 보조 테마도 검색에 포함된다. 브리핑·GitHub digest·RSS는 같은 분류와 원문을 전달한다. 기존 RSS 주소·회차 GUID를 유지한다. 태그가 없는 과거 기사는 전체 목록에서 읽을 수 있지만 추정 분류 필터에는 넣지 않는다.

## 지식 축적과 재검토

매일 `npm run context`의 분류된 최근 사건, 기업명, 기존 주제의 판단·반대 조건·다음 확인을 읽는다. `변화한 사실 → 근거와 수치 → 이전 기록과의 차이 → 다음 확인점`을 남기고 `TREND_WORKFLOW.md`의 Signals·TrendTopics에 연결한다. 이전 비교 수치가 없으면 미확인으로 남긴다.

기업별로 투자·인력·양산·고객·실적을 같은 시간축에서 볼 수 있게 이름을 일관되게 기록한다. 같은 기간에 발생했다는 이유로 인과관계를 단정하지 않는다. 계속 확인할 질문과 실제 근거가 생길 때만 주제를 만든다. 예를 들면 `로봇 기업의 자금 조달이 실제 양산과 고객 도입으로 이어지는가?`다. 질문 예시는 검증된 트렌드 주장이 아니다.

매주 월요일의 기존 8시 실행 안에서 최근 7일과 앞선 기록을 함께 재검토한다. 테마별 수집 건수를 성장률로 해석하지 않고, 수요·성과·투입 역량이 실제로 바뀌었는지 원문 근거로 판단한다. 재사용 원칙은 여러 날짜의 독립 사건과 적용 한계가 확인된 경우에만 기록한다. 별도 주간 예약이나 중복 RSS 회차를 만들지 않는다.
