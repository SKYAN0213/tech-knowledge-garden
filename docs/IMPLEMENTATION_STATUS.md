# 구현 및 운영 상태

## 2026-11-04 기사별 저장 대기 복구 개선

종료된 job을 조회하는 순간 worker 잠금이 해제되면 `ENOENT`로 실패하던 경합을
수정했다. 해당 경합이나 식별할 수 없는 프로세스는 확인 불가로 유지하며,
worker 종료와 재개 가능 여부를 추측하지 않는다.
저장된 완료·대기·실패 상태와 worker 생존 확인은 별도로 표시한다. 확인할 수
없는 worker는 `worker_alive=null`과 재개 불가 상태로 유지해, 저장 상태 확인과
중복 실행 방지 두 계약을 함께 지킨다.

부분 발행처럼 `include_backlog: false`로 지정한 큐레이션 풀이 전역 대기열을
선택한 계획만으로 덮어쓰던 문제를 수정했다. 제한된 풀과 전역 대기열을
분리해 기존 계획과 임시 계획의 범위를 보존한다.

원문 게시일과 사건 발생·기업 발표일을 혼동하게 하는 작성 지시를 수정하고,
사실 추출·독립 검토에도 날짜 귀속의 근거 확인을 명시했다. 추출 지시가
짧은 원문을 불필요하게 분할하지 않도록 같은 조건을 간결하게 유지한다.

괄호 안 리전 표기 `(N. California)`의 약어 마침표를 문장 끝으로 오인하던
오탐을 수정했다. 원문을 보존하며 실제 문장 수 검사는 계속 적용한다.

기사 처리 중 보관된 원문을 다시 받아야 할 때 `STORAGE_PENDING`이 일반
실패로 분류돼 정확한 복원 요청이 누락되는 결함을 수정했다. 해당
기사를 저장 대기로 보존하고 복원 전에는 다른 기사가 처리 슬롯을 사용할 수
있게 했다. 정확한 bytes가 확인되면 기존 writer로 이어가며, 복원 bytes가
다르거나 요청이 유효하지 않으면 차단한다. job 자체가 대기 중일 때는 원 job을
유지한다. 기존 운영 회차에 이미 기록된 실패는 변경하지 않으며 원 요청 복원
뒤 명시 재개한다.

## 2026-11-04 큐레이션 대기 회차 실행본 인계

관계 검토와 큐레이션 평가 중 실행본 수정이 필요한 경우, 선정·기사·정본·외부
발행 이전의 `curation_required` 체크포인트를 별도 수동 구간에 인계한다. 원
수집 보고서·edition·계획·검토·사건 제안 및 소유 job의 실제 입력과 완료 결과를
고정하며 원 회차를 덮어쓰지 않는다. 선정된 적 없는 후보는 계속 보류하고, 기존
미완료 writer는 승인으로 취급하지 않고 원 체크포인트로 이어간다. 이미 승인된
writer는 기존 원문·승인 검증을 유지한다.

인계 전 worker·추가 명령·외부 발행 실행을 검사하며 원 증거가 바뀌면 후속
실행을 차단한다. 실제 운영 인계·Drive 보관·GitHub 발행·수집 완결성은
개발 검사와 별도로 확인한다.

## 2026-11-04 사건 제안 대기 중 실행본 인계

고정된 수집 edition에서 기사·큐레이션·발행이 시작되기 전에 단일 사건 제안
요청을 기다리는 회차를 새 실행본으로 인계할 수 있도록 `continue`를 보완했다.
원 회차·원문·요청·소유 job을 보존하고 중단된 요청만 명시적으로 폐기한다.
동일 입력의 완료된 사건 제안은 기존 캐시에서 재사용하며 새 요청은 새 소유자에
결속한다. 이미 응답이 완료됐거나 worker·중계자가 살아 있거나 후속 쓰기가 있으면
차단한다. 인계와 폐기 근거는 후속 구간의 매 검증에서 다시 확인한다.

인계·요청 중복·worker·회차 검증과 기존 사건 제안 캐시 재사용의 표적 회귀
44/44가 통과했다. 실제 운영의 대기 회차에 대한 읽기 전용 사전 검사에서
원래 요청과 worker 종료, 기존 완료 제안 2개의 재사용 가능성을 확인했다. 이는
운영 전환·모델 재개·발행 완료의 증거가 아니다. 상세 근거는 비공개
`.local/research/development-reviews/tkg-semantic-independent-20261104-r22a/`에
보존한다.

## 2026-11-04 TKG 독립 의미 후보·과거 기사 조회 개발

승인 전 기사에도 사용할 수 있는 로컬 개념 우선순위와 호출 단위 개념 목록
재사용을 개발 트리에 연결했다. 전체 개념 목록·선택 노트·원문 검토와 기존
승인은 유지하며, 우선순위만으로 관계나 `reviewed_none`을 만들지 않는다.
큐레이션의 과거 기사 검색은 원래 후보 결과를 유지하고 반복 정규화와 같은
호출의 기사 이력 재구성을 줄인다. 원문·개념·이력이 바뀌면 결과 저장을
차단하고, 단계별 제어 시간은 모델 시간과 구분한다.

같은 큐레이션 비교에서 후속·정정·상충·계획 이행 관계를 선택적 미검토 후보로
기록할 수 있게 했다. 현재 원문 블록 및 이전 verified 기사 본문과 정확히
일치하는 인용만 저장하고, 별도 모델 호출이나 자동 관계 승인·그래프 기록은
없다. 기존 결과에는 새 필드를 강제로 추가하거나 이전 검토를 반복하지 않는다.

고정 32건(신규 31건·승인 재사용 1건)과 당시 원래 과거 기사 459건·후보
2,908건을 이용해 이전 검색 로직을 같은 코드로 재현한 비공개 단일 프로세스
비교에서 이전 로직 245.814ms, 개선 검색 23.386ms였고 32건의 관련 기사·
후보와 저장된 pool 간 차이는
0건이었다. 원래 이력 파일 592개와 backlog SHA를 전후 확인했다. 이는 해당
검색 단계만의 단일 측정으로 222.428ms 차이이며, 32건 전체 처리·모델 호출·
검토 시간의 단축률은 측정하지 않았다. 명령과 입력 SHA는 비공개
`.local/research/article-acceleration-20261027/semantic-history-search-32-benchmark.mjs`,
결과 SHA `154a0861dbb58393a32908916340f70730f9b5dd28d405f21e3806a391df1971`의
`semantic-history-search-32-1793731706592.json`에 보존한다.

승인 전 후보 축약은 적용하지 않았고 전체 목록 fallback을 유지한다. 변경된
실행 파일을 고정한 상태에서 전체 회귀 2,785/2,785, MCP 회귀 30/30,
TypeScript 검사를 통과했다. 격리된 실제 원문·기존 개념을 대상으로 Luna
편집 검토와 큐레이션 제안을 실행해 기존 검증기에 연결했다. 큐레이션의 첫
응답은 선정된 원문 블록 밖의 인용으로 거부됐고, 범위를 바로잡은 응답은
미승인 제안으로 저장됐다. 이는 비공개 검증이며 발행 승인이 아니다.

검증 근거와 기존 r21의 변경 영향 대조는 비공개
`.local/research/development-reviews/tkg-semantic-independent-20261104-r22/`에
보존한다. 새 실행본의 실제 정규 회차, Drive 반영 및 발행 검증은 별도로
기록한다. 현재 운영 회차의 고정 실행본과 승인·원문을 교체하지 않는다.

## 2026-11-03 비공개 미리보기 렌더러 공유

새 미리보기에서 회차마다 중복하던 렌더러 파일은 입력 SHA로 고정된 읽기 전용
사본 하나를 공유한다. 원고와 생성 결과, 쓰기가 필요한 Quartz 캐시와 웹 소스는
회차별로 유지한다. 백업 대상에서 제외되는 공용 캐시·연결은 정확한 원본이
있을 때 복구하며, 바이트나 연결이 바뀌면 검증을 중단한다. 이전 회차의 출력과
승인·발행 기록은 변경하지 않는다.

실제 운영 vault 969개 파일과 렌더러 527개 파일을 읽기 전용으로 사용한 격리
비교에서, 각 새 미리보기의 렌더러 473개 경로를 공유 대상으로 바꿨다. 기존
방식과 새 방식의 웹 761개와 digest 156개는 사이트맵 생성 시각만 정규화해
내용이 일치했다. 렌더러 준비는 이 단일 시험에서 기존 3.498초, 최초 공유
사본 생성 4.735초, 사본 재사용 0.451초였다. 이는 렌더러 준비만 측정한 값이며
기사 처리 전체나 실제 예약 운행의 단축률이 아니다. 운영 반영과 이후 실제
회차의 결과는 별도로 확인한다.

## 2026-11-02 v32 실제 기사 처리와 비공개 검증

동일한 32건 비공개 실모델 시험의 native 처리와 발행 인계 준비가 완료됐다.
신규 승인 31건, 기존 승인 재사용 1건, 실제 모델 요청 314건이며 모델 동시
실행은 최대 2개, native writer는 최대 1개였다. 운영 쓰기와 공개 발행은 없었다.
이는 시험본의 처리 완료이며 운영 승격을 의미하지 않는다. 독립 감사의 최초
불합격과 후속 정정 결과는 아래에 구분해 기록한다.

원래 타이머의 327,674,880ms에는 며칠간의 중단이 포함된다. 11월 2일 재개부터
완료까지는 11,214,817ms이며, 정확한 중단 시작과 전체 순수 활동 시간은 알 수
없다. 중단 전 상태의 당시 SHA는 기록되어 있으나 계속 갱신된 `latest.json`
현재 경로에서 당시 바이트를 재검증할 수 없다. 원본 측정 결과는 변경하지 않고
`live-v32/measurement-interruption-annotation-20261102.json`에 근거와 한계를
추가했다. 순수 모델 시간과 기존 방식 대비 전체 실모델 단축률은 미측정이다.

v32에 대한 기존 저장 응답 재생에서는 제어·검증 시간이 774,750.839ms에서
55,255.158ms로 줄었고 결과 동등성을 확인했다. 이는 실모델 전체 소요시간의
직접 A/B 비교가 아니다. 32건의 원문·최종 원고 일회성 독립 감사 최초 결과는
6개 기사에서 8개 지적이 나와 불합격이었다. 해당 항목만 독립 재판정한 결과
5개는 불인정, 3개는 정정 필요이며 미해결은 0개다. 세 기사는 필요한 원문
범위를 새로 선정해 정정하고 나머지 29개는 기존 판단을 유지한다.
감사에는 모델 실행 2개가 병렬로 사용됐고 기록된 전체 경과는 1,554,422ms다.
근거는 `live-v32/independent-audit/summary.json`과 그 아래
`adjudication/summary.json`이다. 당시 이후 바뀐 개발 코드는 v32 시험과 구분한다.
이 네 파일 중 수집 복구·선정 이력·검증 입력 캐시의 변경 구간을 대상으로 한
추가 회귀 13건은 모두 통과했으며, 실행 전후 코드·테스트 SHA가 일치했다.
실행 기록은 `migration-evidence/article-acceleration-focused-20261102T054723Z.json`이다.
일회성 독립 감사에서 한 기사의 Nscale 시험 규모 누락을 지적했으나, 고정된
최종 원고에는 동일 조건인 GB300 NVL72 랙 4대가 실제로 기재되어 있다. 같은
감사에 기록된 별도 라이브러리 출시 누락과 함께 최초 판정을 보존하고 정확한
원문·선정 범위·최종 원고에 한정해 독립 재판정한 결과 두 지적은 불인정이었다.
이는 전체 32건의 감사 통과나 필요한 정정 완료를 의미하지는 않는다.
감사 결과 중 16개의 자체 기록 시각이 실제 실행 관측과 일치하지 않았다. 그
시각을 고치거나 감사 근거로 합성하지 않으며, 전체 감사 경과는 별도 기록된
실행 수락부터 결과 확인까지 계산한다. 최초 요약의 기사별 시각 범위는 신뢰하지
않는다. SHA와 불일치 범위는 `independent-audit/timing-observation-20261102.json`에
기록했다.

정정 시험 중계는 기존 native relay planner를 이용해 같은 기사·역할 단계의
완료된 실행자 문맥을 다음 요청에 재사용한다. 요청 소유 job·SHA·모델을 다시
확인하며, 기사나 역할 단계가 달라지거나 작성자와 최종 검토자가 겹치면 새
실행자를 요구한다. 동시 실행 두 자리와 운영용 한 자리를 유지한다. 표적 검사
3건은 통과했고 실제 정정 요청에서 재사용을 시작했다. 이 중계 보완은
`live-v32/independent-audit/adjudication/correction-plans/record-quality-actor-v2.mjs`의
비공개 시험용이며 아직 운영 실행본에 배포한 기능은 아니다.

후속 정정 감사에서는 두 기사가 새 승인과 독립 감사를 통과했다. 나머지 기사는
기존 승인에 있던 실제 완주 시간의 누락이 확인돼 최초 정정과 실패 감사 결과를
보존하고 해당 원문 블록을 추가한 새 선정으로 다시 처리한다. 전체 32건을 다시
처리하지 않는다. 이 과정에서 단독 `validation.revise_draft` job의 모델 대기
요청을 중계 계획기가 인식하지 못하는 결함을 재현했다. 개발 트리는 고정 job
입력·소유권·기사 ID와 요청 SHA가 일치하는 경우에만 해당 요청의 배정을 제안한다.
관련 중계 검사 11/11, MCP 서버 검사 11/11 및 변경한 두 코드·테스트 파일의
