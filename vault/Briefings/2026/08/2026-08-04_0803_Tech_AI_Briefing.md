## 음성 AI, 말하기와 깊은 생각을 서로 막지 않게 분리하다

OpenAI는 8월 3일 GPT‑Live를 대규모로 운영하기 위해 만든 실시간 음성 아키텍처를 공개했습니다. 사용자의 말을 듣고 답하는 흐름은 계속 유지하면서, 검색이나 복잡한 추론은 별도 경로에서 처리하는 방식입니다.

**핵심 사실**

- GPT‑Live는 별도 발화 종료 감지기가 결정을 내릴 때까지 기다리지 않고 음성을 계속 받아들이고 내보냅니다.
- 음성 전송 전용 경로와 애플리케이션·도구 호출 경로를 분리해, 느린 도구 호출이 대화 자체를 멈추지 않게 했습니다.
- 긴 대화의 문맥을 줄이거나 모델 인스턴스를 바꿀 때도 기존 인스턴스를 유지한 채 새 인스턴스를 준비한 뒤 전환합니다.
- OpenAI는 새 전송 절차 WARP가 미디어 시작에 필요한 네트워크 왕복을 6회에서 1회로 줄인다고 설명했습니다. 이는 회사가 공개한 자체 시스템 수치입니다.
- 실제 음성을 사용자에게 내보내지 않는 읽기 전용 그림자 테스트로 용량, 지역별 지연, 장시간 세션, 재연결 문제를 점검했습니다.

**왜 중요한가**

음성 AI의 품질은 모델 하나의 성능만으로 결정되지 않습니다. 음성 전송, 세션 상태, 문맥 압축, 도구 호출, 지역별 서버 용량이 함께 맞아야 자연스럽게 반응합니다. 실시간 대화와 깊은 작업을 분리하는 구조는 음성으로 에이전트를 지시하고 중간에 개입하는 제품의 기본 설계가 될 수 있습니다.

**앞으로 볼 점**

예정된 GPT‑Live API가 나올 때 지연 시간 측정, 대화·도구 실행 기록, 데이터 처리 정책이 개발자에게 얼마나 공개되는지 봐야 합니다.

## Orchard, 실제 실행 환경에서 에이전트를 훈련하고 평가하다

Microsoft Research는 8월 3일 에이전트 연구용 오픈소스 프레임워크 Orchard를 공개했습니다. 핵심은 코딩, 웹 탐색, 개인 비서처럼 서로 다른 작업을 같은 격리 환경 서비스에서 훈련하고 평가하는 것입니다.

- **프로젝트:** Microsoft Orchard
- **쉬운 설명:** 에이전트마다 별도 샌드박스와 평가 시스템을 다시 만들지 않고, Kubernetes 기반 격리 환경을 공통으로 재사용합니다. Codex 같은 실제 배포용 실행기 안에서 학습 데이터를 모으고 평가할 수도 있습니다.
- **확인된 결과:** Microsoft는 약 30억 개의 활성 매개변수를 쓰는 Orchard‑SWE가 SWE‑bench Verified에서 69.7%, 별도 가치 모델로 후보를 다시 고르면 73.0%를 기록했다고 보고했습니다. 수치는 연구팀의 설정과 벤치마크 결과이며 독립 재현 결과는 아닙니다.
- **공개 범위:** 환경 서비스, 훈련 파이프라인, 코드, 학습 데이터, 평가 방법을 공개했습니다.
- **GitHub:** https://github.com/microsoft/Orchard
- **Star 증가 추세:** 추세 확인 불가
- **어디에 쓸 수 있나:** 코딩·브라우저·업무 에이전트의 샌드박스 실행, 강화학습 반복 실행, 실행기별 성능 비교에 쓸 수 있습니다.
- **한계:** 높은 점수가 다른 저장소나 실제 조직 업무에서도 그대로 이어지는지는 별도 검증이 필요합니다. Kubernetes 운영 비용, 데이터 출처, 평가 실행기 설정도 함께 확인해야 합니다.
