# GitHub Apps 기업 설치 GA…정책·보안·관리 API 지원 확대


GitHub는 2026년 10월 23일 GitHub Apps의 기업 설치를 정식 제공(GA)하고, 기업·조직의 정책·보안·관리 API 지원을 확대했다고 발표했다. 지원 범위가 넓어지면서 더 많은 기업·조직 자동화에서 클래식 PAT를 GitHub Apps로 대체할 수 있게 됐다고 회사는 설명했다. [원문 1](<https://github.blog/changelog/2026-10-23-enterprise-installations-for-github-apps-generally-available>)

### 정책 권한과 필수 설정 읽기

Enterprise organization and repository policies 권한은 Read/write로, EnterpriseOwnerInfo의 정책 필드를 읽고 비공개 저장소 포크·기본 저장소 권한·저장소 공개 범위·저장소 생성과 삭제·이슈 삭제·협력자 초대·배포 키·보호 브랜치 갱신·dependency insights·조직 및 저장소 프로젝트 설정을 변경하는 API를 지원한다.

Enterprise settings는 Read/write로 기업 데이터, 서버 설치와 조직 초대 정보를 읽고 기업 프로필을 갱신한다. 기업 조직·저장소 정책에 접근하려면 이 Enterprise settings의 Read 권한이 필요하다. [원문 1](<https://github.blog/changelog/2026-10-23-enterprise-installations-for-github-apps-generally-available>)

### 보안과 규칙 관리의 권한 차이

기업·조직 IP 허용 목록은 Read/write로 항목 읽기·생성·수정·삭제를 지원한다. 허용 목록 적용, GitHub Apps 신뢰 설정, Enterprise Managed Users의 사용자 수준 적용도 전환할 수 있다.

기업 접근 제한은 Write 권한으로 켜거나 끌 수 있다. 기업 저장소 규칙 집합도 Write 권한으로 기업 rules REST API와 GraphQL의 RepositoryRuleset을 통해 관리한다.

Enterprise bypass requests는 Read, 기업 2단계 인증은 Read/write, 기업·조직 검증 도메인은 Write로 구분된다. [원문 1](<https://github.blog/changelog/2026-10-23-enterprise-installations-for-github-apps-generally-available>)

### 기존 권한의 API 보완과 이전 조건

기존 Enterprise people Read/write 권한에서는 EnterpriseRepositoryInfo를 읽으며, EnterpriseOwnerInfo.outsideCollaborators를 통한 저장소 세부 정보도 확인할 수 있다. 지원 API 항목에는 자신을 소유자 또는 구성원 역할로 조직에 추가하는 작업도 포함된다.

Enterprise billing Write 권한은 Marketplace의 구성원 구매 설정 갱신을 지원한다. GitHub는 이런 API·객체 지원 보완이 더 많은 자동화 시나리오를 가능하게 할 것으로 설명했다.

이전할 워크플로에 필요한 권한은 사용자가 GitHub App에서 선택해야 한다. 해당 업데이트의 GHES 3.24 제공은 향후 예정이다. [원문 1](<https://github.blog/changelog/2026-10-23-enterprise-installations-for-github-apps-generally-available>)
