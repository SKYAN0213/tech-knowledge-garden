# GitHub, 비밀정보 경보가 남은 PR의 병합을 막는 규칙 공개


GitHub는 9월 9일 비밀정보 경보가 남아 있는 풀 리퀘스트(PR)의 병합을 차단하는 저장소 규칙을 공개 미리보기로 제공한다고 발표했다. GitHub Secret Protection 또는 Advanced Security 고객이 규칙을 켜면 최신 커밋의 비밀정보 검사가 완료되고 해당 PR이 도입한 비밀정보의 열린 경보가 없어야 병합할 수 있다. 기본 탐지 대상은 서비스 제공자 패턴이며, 사용자 정의·일반 패턴은 추가로 설정할 수 있고 우회 권한이 없는 개발자는 경보를 해결해야 차단을 해제할 수 있다. [원문 1](<https://github.blog/changelog/2026-09-09-block-pull-requests-with-exposed-secrets-from-merging/>)

### 푸시 단계와 병합 단계의 보호

푸시 보호는 비밀정보가 저장소에 들어오기 전에 차단한다. 새 규칙은 PR 병합 단계에서 추가로 검사하므로, 푸시 보호에서 검사하지 않도록 설정한 일반 패턴도 병합 규칙의 대상으로 지정할 수 있다. [원문 1](<https://github.blog/changelog/2026-09-09-block-pull-requests-with-exposed-secrets-from-merging/>)

### 브랜치별 규칙과 API 설정

저장소·조직·엔터프라이즈의 Repository → Rulesets에서 보호할 브랜치를 지정하고 Require secret scanning alerts are resolved를 선택한다. REST API에서는 require\_secret\_scanning\_alert\_resolution과 secret\_types로 같은 규칙을 설정할 수 있다. [원문 1](<https://github.blog/changelog/2026-09-09-block-pull-requests-with-exposed-secrets-from-merging/>)
