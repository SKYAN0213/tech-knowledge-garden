# AWS, 데이터 검색·SQL 실행 단계별 권한을 적용하는 에이전트 구조 제시


AWS는 2026년 6월 26일(한국시간), 고객 서비스 에이전트가 여러 데이터 소스를 조회할 때 접근 권한을 단계별로 적용하는 데이터 메시 구현 글을 공개했다. 예제는 S3 Tables·Lake Formation·Athena로 정형 데이터를, S3 Vectors와 Bedrock Knowledge Bases로 비정형 자료를 조회하고 AgentCore Gateway의 MCP 도구로 연결한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-agentic-ai-applications-with-a-modern-data-mesh-strategy-on-aws/>)

### 조회 도구와 권한 경계

get\_user\_tables는 허용된 테이블을, get\_schema는 스키마를 조회한다. run\_query는 읽기 전용 SQL과 고객 식별자를 Athena에 전달하며, kb\_search는 메타데이터 필터를 적용한 의미 검색을 수행한다.

Gateway의 요청 인터셉터는 도구 실행 전에 JWT 범위를 확인한다. 응답 인터셉터는 허용되지 않은 도구를 목록에서 제거하고 반환 데이터의 민감 정보를 가리는 역할을 맡는다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-agentic-ai-applications-with-a-modern-data-mesh-strategy-on-aws/>)

### 고객별 행과 검색 범위

Lake Formation의 행 단위 보안은 인증된 고객의 customer\_id에 맞는 행만 조회하도록 제한한다. 예제는 run\_query에서 고객 식별자를 전달하고, 열 단위 보안으로 payment\_method·billing\_address를 숨기는 방식을 제시한다.

kb\_search의 메타데이터 필터링은 제품 분류·문서 유형 같은 속성으로 검색 범위를 좁힌다. 예제에서는 전자제품의 반품 정책만 검색하도록 조건을 지정한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-agentic-ai-applications-with-a-modern-data-mesh-strategy-on-aws/>)

### SQL 실행 제어

Athena 작업 그룹은 쿼리의 데이터 스캔 한도를 적용하고, 읽기 전용 IAM 정책은 데이터 카탈로그 변경을 차단한다. AWS는 도구 호출 권한 검사와 모델의 SQL 작성이 별개임을 구분하고 이런 제어를 함께 적용했다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-agentic-ai-applications-with-a-modern-data-mesh-strategy-on-aws/>)
