# GitHub CLI, 만료형 자동 갱신 OAuth 자격 증명 공개 프리뷰


GitHub는 2026년 10월 22일(한국시간) GitHub CLI의 만료형 자동 갱신 OAuth 자격 증명을 공개 프리뷰로 제공한다고 밝혔으며, 사용자가 기능을 켜면 gh가 만료형 액세스 토큰과 회전하는 리프레시 토큰을 함께 저장해 필요할 때 액세스 토큰을 갱신하고 재인증 없이 인증을 유지하며 유출된 액세스 토큰은 무기한 유효한 것이 아니라 몇 시간 안에 사용할 수 없게 된다고 설명했다. GitHub는 시작하려면 GitHub CLI v2.103.0을 설치하거나 업그레이드한 뒤 로그인 때 `--expiring`을 지정하거나 `gh config set expiring_credentials enabled`를 실행하라고 안내했으며, 설정하면 gh는 별도 일상 명령 없이 백그라운드에서 자격 증명을 갱신하고 `gh auth status`에서 상태와 현재 액세스 토큰의 만료 시점을 확인할 수 있다. GitHub 설명에 따르면 만료형 토큰은 게시일 기준 github.com과 ghe.com에서 이용할 수 있고 GitHub Enterprise Server는 GHES 3.23부터 발급하며, 그 이전 버전이나 이를 지원하지 않는 서버에서는 비만료 토큰 동작으로 대체된다. 이 기능은 선택 적용으로 기존 로그인과 직접 제공한 토큰은 그대로 작동하며, GitHub는 향후 릴리스에서 신규 로그인에 기본값으로 적용할 계획이라고 밝혔다. [원문 1](<https://github.blog/changelog/2026-10-21-github-cli-opt-in-to-expiring-auto-refreshing-oauth-tokens>)

### HTTPS Git 사용 조건

HTTPS로 Git에 인증하면서 만료형 토큰을 쓰려면 GitHub는 `gh auth setup-git`으로 gh를 Git 자격 증명 도우미로 설정하라고 강력히 권장한다. GitHub는 토큰이 수명 이후 캐시되지 않도록 Git 2.46 이상으로 업그레이드할 것도 강력히 권하며, 이전 버전에서도 gh는 작동하지만 업그레이드 권고를 한 번 표시한다. [원문 1](<https://github.blog/changelog/2026-10-21-github-cli-opt-in-to-expiring-auto-refreshing-oauth-tokens>)

### 토큰을 저장해 쓰는 작업 흐름

`gh auth token`의 결과를 저장해 나중에 재사용하거나 토큰을 다른 도구에 복사하는 스크립트·확장은 토큰이 만료된 뒤 실패할 수 있다. gh 바깥에서 토큰을 쓸 때는 `gh auth token`을 사용할 때마다 새로 읽어야 하며, 이 명령은 필요할 때 토큰을 갱신하고 값을 캐시하지 않는다. GitHub는 장기간 유효한 토큰이 필요한 작업 흐름에서는 해당 작업에 만료형 토큰을 적용하지 말라고 안내하며, Git 자격 증명 도우미를 사용하면 gh가 자격 증명을 갱신해 HTTPS Git 작업을 이어간다. [원문 1](<https://github.blog/changelog/2026-10-21-github-cli-opt-in-to-expiring-auto-refreshing-oauth-tokens>)
