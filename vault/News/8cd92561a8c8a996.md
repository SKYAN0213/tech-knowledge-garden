# AWS, A2A 게이트웨이 참조 구현 공개…검색·권한·라우팅 통합


AWS는 7월 2일(한국시간) 여러 에이전트를 단일 도메인과 경로 기반 라우팅으로 연결하는 서버리스 A2A 게이트웨이 참조 구현 가이드를 공개했다. AWS는 ECS·Lambda·AgentCore Runtime뿐 아니라 다른 클라우드와 하이브리드 환경의 에이전트도 특정 런타임이나 프레임워크에 종속되지 않고 연결할 수 있다고 설명했다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-a-serverless-a2a-gateway-for-agent-discovery-routing-and-access-control/>)

### 등록·검색·접근 권한

구현은 관리·제어·실행의 세 계층으로 나뉜다. 관리 계층은 에이전트 등록과 검색, 제어 계층은 JWT 스코프와 Lambda authorizer를 통한 접근 권한, 실행 계층은 라우팅·OAuth 백엔드 인증·SSE 스트리밍을 맡는다.

에이전트 설명은 Amazon Titan Text Embeddings로 임베딩한 뒤 Amazon S3 Vectors에 저장한다. 클라이언트는 정확한 이름 대신 자연어 검색어로 에이전트를 찾을 수 있다.

Amazon API Gateway의 REST API는 SSE 응답 스트리밍을 위한 단일 진입점이다. Lambda authorizer는 JWT 스코프를 검사해 특정 에이전트 경로를 허용하거나 거부하는 IAM 정책을 만든다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-a-serverless-a2a-gateway-for-agent-discovery-routing-and-access-control/>)

### 호출 방식과 백엔드 자격 증명

표준 A2A 클라이언트는 수정 없이 사용할 수 있다. 게이트웨이는 JSON-RPC와 HTTP+JSON/REST 바인딩을 모두 지원하며, 에이전트 카드 조회·일반 응답을 위한 SendMessage·SSE 스트리밍을 위한 SendStreamingMessage를 처리한다.

모든 백엔드 에이전트에는 OAuth 인증이 활성화돼 있어야 하며, 프록시는 OAuth 2.0 클라이언트 자격 증명 흐름으로 토큰을 얻는다. 백엔드 클라이언트 시크릿은 DynamoDB 대신 AWS Secrets Manager에 저장하고, Proxy Lambda가 ARN으로 조회한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-a-serverless-a2a-gateway-for-agent-discovery-routing-and-access-control/>)

### 사용자·에이전트별 요청 제한

프록시는 사용자·에이전트·분 단위로 구분한 DynamoDB 원자 카운터로 요청 수를 센다. 한도를 넘으면 백엔드에 요청을 보내지 않고 HTTP 429와 retry-after 헤더를 반환한다. 카운터는 DynamoDB TTL로 자동 만료된다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-a-serverless-a2a-gateway-for-agent-discovery-routing-and-access-control/>)

### 프라이빗 배포와 메시지 처리 범위

선택적 VPC 모드에서는 Lambda가 프라이빗 서브넷에서 실행되고 API Gateway는 VPC 내부에서만 접근할 수 있는 프라이빗 엔드포인트로 전환된다. 이 모드에서도 Cognito나 다른 외부 인증 제공자와 OAuth 토큰을 교환하려면 외부 인터넷 연결이 필요하다.

AWS가 설명한 참조 구현은 백엔드 등록과 OAuth 자격 증명 검증 후 응답 내용을 검사하지 않고 전달하며, A2A 메시지도 수정하지 않는다. 프롬프트 인젝션 방어와 입력 검증은 백엔드 에이전트가 수행한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/building-a-serverless-a2a-gateway-for-agent-discovery-routing-and-access-control/>)
