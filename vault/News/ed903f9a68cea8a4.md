# PAR, 고객별 데이터 경계를 SQL 앞단에서 강제하는 분석 에이전트 공개


PAR Technology는 2026년 6월 30일(한국시간) AWS 공식 블로그에서 다중 고객용 자연어 분석 에이전트의 보안 구조를 소개했다. AWS SigV4 요청 서명, Bedrock의 질문 검토, 서버가 생성하는 행 단위 데이터 필터를 결합해 LLM이 조회할 수 있는 범위를 먼저 한정한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/multi-tenant-llm-analytics-with-row-level-security-how-we-built-a-secure-agent-on-aws/>)

### 권한은 프롬프트가 아니라 서버에서 결정

요청에는 Tenant ID·Business ID·Admin ID를 넣고 SigV4로 서명한다. 검증 뒤 세 값을 합친 세션 키를 만들어 후속 처리를 해당 사용자 문맥에 묶는다. PAR는 처음에는 프롬프트에 사업체 ID 필터를 지시했지만, 운영 단계에서는 모델의 필터 누락 가능성을 보안 경계로 받아들일 수 없어 구조를 바꿨다고 설명했다.

질문이 지원되는 지표에 해당하는지 확인하는 단계는 인증 뒤, 데이터 접근 전에 실행한다. 매출 금액과 매출 건수처럼 의미가 모호하면 질문 구체화를 요청하고 SQL 생성을 진행하지 않는다.

서버는 검증된 사용자 ID를 기준으로 공통 테이블 식(CTE)을 생성해 허용된 행만 남긴다. 모델에는 원본 테이블이 아니라 이 CTE의 열 이름·자료형만 전달하고, 모델이 만든 분석 SQL을 서버의 CTE와 결합해 Databricks에서 실행한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/multi-tenant-llm-analytics-with-row-level-security-how-we-built-a-secure-agent-on-aws/>)

### 회사에서 보고한 운영 결과

PAR는 해당 구조로 운영 환경에서 5만 건이 넘는 쿼리를 처리했으며 고객 간 데이터 노출 사고는 없었다고 밝혔다. 이는 회사가 보고한 해당 구현의 운영 결과다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/multi-tenant-llm-analytics-with-row-level-security-how-we-built-a-secure-agent-on-aws/>)
