# AWS, 의료 청구 PDF를 FHIR로 변환하는 에이전트 구현 예시 공개


AWS는 2026년 6월 30일(한국시간) Bedrock Data Automation·AgentCore·HealthLake를 연결한 의료 청구 처리 샘플을 공개했다. CMS-1500 PDF를 S3에 올리면 서류를 JSON으로 추출하고, 에이전트가 환자·의료진·보험 기록과 대조한 뒤 조건을 충족한 청구를 FHIR 자원으로 저장한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/build-an-agentic-ai-healthcare-claims-pipeline-with-amazon-bedrock-and-aws-healthlake/>)

### 고정 처리 순서와 에이전트 검색을 분리

Lambda는 문서 업로드에 반응해 처리를 시작하고, 처리 완료 또는 예외 큐 전달 여부를 감독한다. Bedrock Data Automation의 blueprint는 서식 차이가 있는 CMS-1500에서 필요한 항목을 일정한 JSON 구조로 추출하며 필드 신뢰도와 위치 정보도 제공한다.

Strands 에이전트는 HealthLake 검색과 FHIR 청구 생성을 위한 두 도구를 사용한다. 기본 검색으로 참조 기록을 찾지 못하면 추출 신뢰도가 높은 속성으로 두 번 더 검색하고, 식별 근거를 설명하도록 구성했다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/build-an-agentic-ai-healthcare-claims-pipeline-with-amazon-bedrock-and-aws-healthlake/>)

### 담당자·환자에게 전달하는 처리 결과

처리 결과는 청구 담당자용 기술 요약과 환자에게 전달할 쉬운 설명으로 나누어 SNS로 보낸다. 샘플의 성공 시나리오는 식별자 끝의 숫자 0과 문자 O가 다른 상황을 넣어 다른 검색 정보로 기록을 대조하는 과정을 보여준다.

이 글은 샘플 데이터로 실패·성공 흐름을 시연한다. AWS는 알려진 처리 순서를 코드로 정하고 Lambda를 최종 성공·실패 판단자로 두는 설계 방식을 설명했다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/build-an-agentic-ai-healthcare-claims-pipeline-with-amazon-bedrock-and-aws-healthlake/>)
