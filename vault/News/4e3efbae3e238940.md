# GitHub Copilot 사용량 API, OpenCode 등 도구별 요청·토큰 집계 추가


2026년 10월 24일(한국시간) GitHub는 Copilot 사용량 지표 API가 OpenCode처럼 기존 보고서에 잡히지 않던 도구의 모델 사용량도 보고하도록 확장하고 `totals_by_client` 배열을 추가했다고 밝혔다. 새 집계는 엔터프라이즈·조직·사용자 단위 보고서의 1일 및 28일 버전에 적용되며, 28일 통합 보고서에서는 날짜별 `day_totals` 항목에 표시된다. GitHub는 IDE 밖 도구가 편집기 telemetry를 보내지 않아 `totals_by_ide`에서 빠졌던 사용량을 서버 요청 집계로 보완해, 도구별 사용과 요청·토큰 규모를 파악하고 지원·거버넌스 결정을 내릴 수 있다고 설명했다. [원문 1](<https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode>)

### 도구별 집계 필드

각 `totals_by_client` 항목은 하나의 client를 나타낸다. `client`에는 요청을 보낸 도구가 표시되며 예시는 `opencode`, `claude_code`, `codex`, `zed`, `copilot_cli`, `github_app`, `cloud_agent`, `code_review`, `vscode`, `jetbrains`다. 인식되지 않은 값은 `other`로 묶인다.

`request_count`는 해당 client의 성공한 모델 요청 수다. 이는 prompt 수가 아니라 model call 수이므로 한 prompt가 여러 call을 만들 수 있고, prompt나 interaction 횟수와 직접 비교해서는 안 된다. `session_count`는 서로 다른 세션 수이며 `token_usage`는 prompt token, output token, 요청당 평균 token을 담는다.

`totals_by_model`은 요청·token 지표를 모델별로 나눈다. `model_selection_mode`는 직접 요청한 `user_selected`, 자동 선택 `auto`, 제품이 고른 `product_selected`를 구분하고, 아직 개별 보고되지 않는 선택 방식은 `other`, 정규화할 수 없는 값은 `unknown`으로 나타난다. Copilot code review와 cloud agent는 제품이 모델을 고르므로 `product_selected`이며, code review 모델은 `unknown`으로 보고된다. [원문 1](<https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode>)

### 식별·접근 조건과 호환성

GitHub는 각 요청에 실린 integration ID로 client를 식별한다. 따라서 `client`는 실제 도구 신원을 검증한 값이 아니라 요청에 담긴 ID를 바탕으로 한 best-effort 그룹이다. 이 API의 `totals_by_client`는 Copilot을 사용하는 모든 도구의 모델 traffic, 즉 요청과 토큰을 측정한다. 이는 Claude나 Codex 같은 GitHub agent app이 시작한 job 수를 집계하는 agent app activity와는 다른 지표다.

이 지표는 엔터프라이즈 소유자와 billing manager, 조직 소유자, 또는 `View Copilot Metrics` 권한을 가진 사용자 지정 조직·엔터프라이즈 역할이 볼 수 있다. Copilot usage metrics 정책도 활성화되어 있어야 한다.

GitHub는 변경이 추가 방식이라 기존 필드는 그대로 유지되고, 보고할 사용량이 없으면 `totals_by_client`가 빈 배열이라고 밝혔다. [원문 1](<https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode>)
