# vLLM 0.24.0, 스트리밍 도구 파서·모델 지원·서버 보안 변경


vLLM 프로젝트는 2026년 6월 30일(한국시간) 0.24.0을 공개했다. MiniMax-M3·DiffusionGemma 지원, 모델별 도구 호출과 추론 출력을 통합하는 Streaming Parser Engine, Rust 프런트엔드 인증 기능 등을 추가했다. [원문 1](<https://api.github.com/repos/vllm-project/vllm/releases/tags/v0.24.0>)

### 모델 실행과 응답 파싱

Model Runner V2는 양자화 모델을 기본 지원하고 Qwen·DeepSeek-V2 MoE 실행 경로와 DFlash 추측 디코딩을 확장했다. DiffusionGemma에는 CPU 실행 경로와 구조화 출력 제어가 추가됐다.

새 스트리밍 파서 엔진에는 Qwen3·MiniMax-M2·GLM·Nemotron 계열 파서가 포함된다. Chat Completions와 Responses API의 도구 호출에는 strict mode를 추가했다. [원문 1](<https://api.github.com/repos/vllm-project/vllm/releases/tags/v0.24.0>)

### 운영 시 달라지는 서버 설정

Rust 프런트엔드는 API 키 인증·CORS·토큰화·요청 중단·일시 정지와 재개를 지원한다. thinking\_token\_budget, parallel\_tool\_calls 설정 및 사용량 통계도 추가됐다.

장치 선택에서는 vLLM이 내부에서 CUDA\_VISIBLE\_DEVICES를 설정하던 동작을 없애고 device\_ids 인자를 제공한다. ROCm에서는 기존 환경 변수에 대해 폐기 전환 기간을 시작했다. [원문 1](<https://api.github.com/repos/vllm-project/vllm/releases/tags/v0.24.0>)

### 서비스 거부와 의존성 보안 수정

보안 변경에는 오디오 압축 폭탄·잘못된 복구 토큰 재삽입·prompt\_embeds를 이용한 서비스 거부 대응, 오디오 업로드 크기와 디코딩 시간 제한, 구조화 출력의 정규식 컴파일 시간 제한이 포함된다.

Starlette 의존성은 CVE-2026-48710 대응을 위해 1.0.1 이상으로 올렸다. [원문 1](<https://api.github.com/repos/vllm-project/vllm/releases/tags/v0.24.0>)
