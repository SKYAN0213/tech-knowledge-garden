# GitHub Public monitoring에 경보 관리·데이터 레지던시 지원 추가


GitHub는 한국시간 2026년 10월 24일 Public monitoring에 경보 관리 기능을 더해 기업 고객이 엔터프라이즈 보안 대시보드에서 공개 모니터링 결과를 분류·처리할 수 있다고 밝혔다. 관리자는 경보를 Dismissed 또는 Fixed로 닫고 선택적으로 설명을 남기거나, 상황이 바뀌면 닫힌 경보를 다시 열 수 있다. 하루 앞선 한국시간 10월 23일에는 Public monitoring을 GitHub Enterprise Cloud 데이터 레지던시 고객에게도 공개 프리뷰로 제공한다고 발표했다. 데이터 레지던시 환경에서는 검증된 도메인 일치만으로 조직 귀속을 판정하고, 일치한 경보를 암호화해 해당 기업 대시보드에 전달하며 지정된 지리 범위 안에 데이터를 유지한다고 GitHub는 설명했다. [원문 1](<https://github.blog/changelog/2026-10-23-public-monitoring-adds-triage-validity-api-and-webhooks>) [원문 2](<https://github.blog/changelog/2026-10-22-public-monitoring-now-available-with-data-residency>)

### 토큰 상태와 경보의 한계

GitHub는 지원되는 provider의 토큰 유효성을 계속 자동 확인하고 경보에 Active, Inactive, Unknown 상태를 표시한다고 밝혔다. 이 구분은 보안팀이 활성 토큰을 우선 대응하도록 돕는 기능이다.

경보를 닫으면 엔터프라이즈의 경보 상태만 바뀐다. 노출된 자격 증명이 폐기되거나 공개 저장소에서 삭제되는 것은 아니라고 GitHub는 명시했다. [원문 1](<https://github.blog/changelog/2026-10-23-public-monitoring-adds-triage-validity-api-and-webhooks>)

### 대시보드 감사와 필터

경보 활동 타임라인은 경보에 취해진 모든 조치와 상태 변경의 감사 기록을 제공한다. 목록은 저장소, 커미터, 비밀정보 유형, 귀속 방식(멤버십 또는 검증된 도메인), 열린 상태·닫힌 상태로 필터링하고 정렬할 수 있다. [원문 1](<https://github.blog/changelog/2026-10-23-public-monitoring-adds-triage-validity-api-and-webhooks>)

### 대응 파이프라인 연결

엔터프라이즈 관리자와 엔터프라이즈 보안 관리자는 GET /enterprises/{enterprise}/secret-scanning/public-monitoring-alerts REST API로 귀속된 발견사항을 조회할 수 있다. 반환 항목에는 경보 메타데이터, 비밀정보 유형, 귀속 정보와 노출 위치가 포함된다.

조직은 enterprise 수준에서 secret\_scanning\_public\_monitoring\_alert webhook을 구독해 새로 탐지된 유출이 조직에 귀속될 때 실시간 알림을 받을 수 있다. [원문 1](<https://github.blog/changelog/2026-10-23-public-monitoring-adds-triage-validity-api-and-webhooks>)

### 공개 프리뷰와 라이선스

Public monitoring은 GitHub Enterprise Cloud 고객을 대상으로 공개 프리뷰 상태이며, 데이터 레지던시 고객도 포함된다. Enterprise admin 또는 enterprise security manager가 보안 대시보드에서 기능을 켜고 경보 설정을 관리할 수 있으며, 사용에는 활성 GitHub Advanced Security 또는 GitHub Secret Protection 라이선스가 필요하다. 기능은 해당 라이선스에 추가 비용 없이 포함된다.
