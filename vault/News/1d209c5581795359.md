# Cloudflare, AI 크롤러 제어 확대…9월 차단 정책·콘텐츠 과금 계획 공개


TechCrunch는 한국시간 7월 2일 Cloudflare의 AI 크롤러 정책과 콘텐츠 사용에 따른 과금 실험을 보도했다. Cloudflare가 한국시간 7월 1일 공개한 내용에는 목적별 접근 제어, 9월 적용 예정인 기본 차단 정책, Monetization Gateway 도입 계획이 포함됐다. [원문 1](<https://techcrunch.com/2026/07/01/cloudflares-new-policy-pushes-ai-companies-to-pay-for-publishers-content/>) [원문 2](<https://blog.cloudflare.com/making-ai-search-smarter/>) [원문 3](<https://blog.cloudflare.com/content-independence-day-ai-options/>) [원문 4](<https://blog.cloudflare.com/monetization-gateway/>)

### 목적별 접근 제어와 9월 정책

발표 당시 Search·Agent·Training별 AI 트래픽 설정은 Free 요금제를 포함한 모든 기존 고객에게 제공 중이었다. 고객은 각 사이트의 Settings에서 이를 구성할 수 있다.

9월 15일에는 Cloudflare에 새로 등록하는 도메인의 광고 표시 페이지에서 Training과 Agent 크롤러를 기본 차단하고 Search를 기본 허용할 계획이다. Search와 Training을 함께 수행하는 Googlebot·Applebot·BingBot 등에는 가장 제한적인 규칙이 적용돼 Training 차단을 선택한 고객에게 차단된다. 사이트 소유자는 시행 전 Security 설정에서 변경 적용을 거부할 수 있다.

BotBase의 검색 가능한 봇 목록은 Enterprise Bot Management 고객에게 제공 중이며, 직접 제어 센터로의 확대는 그해 후반 계획이다. Verified 표시는 해당 목적 분류의 허용 규칙에 따라 접근할 수 있다는 뜻으로 바뀌며, 검증된 봇을 일괄 허용하는 기본값과 구분된다. [원문 3](<https://blog.cloudflare.com/content-independence-day-ai-options/>)

### 콘텐츠 사용 신호와 검색 연구

Cloudflare는 robots.txt의 Content Signals에 use 항목을 추가하는 실험도 시작했다. immediate는 상호작용 후 저장·재사용하지 않는 선호, reference는 색인·발췌·원문 링크, full은 요약·재생산의 선호를 나타낸다. 이 값은 사이트 소유자의 의사를 표시하며 직접 접근을 차단하지 않는다.

별도로 시작한 AI 검색 연구는 고객이 공유하기로 선택한 콘텐츠 최신성 신호와 사람·봇의 네트워크 트래픽 관찰을 결합한다. Cloudflare는 검색 결과의 최신성·품질과 불필요한 크롤링 감소를 측정할 계획이라고 설명했다. 연구는 검색에 한정되며 콘텐츠를 공유하거나 파운데이션 모델 학습에 사용하지 않는다.

Cloudflare는 이 검색 기능을 그해 후반에 더 넓게 제공할 계획이라고 밝혔다. [원문 3](<https://blog.cloudflare.com/content-independence-day-ai-options/>) [원문 2](<https://blog.cloudflare.com/making-ai-search-smarter/>)

### Pay Per Use의 두 실험

Pay Per Use는 콘텐츠를 가져간 횟수에 대한 Pay Per Crawl에서 콘텐츠가 실제 사용되는 경우의 대가로 옮기는 실험이다. Cloudflare는 Ceramic.ai와 You.com의 결제 모델을 콘텐츠 소유자에게 연결하는 실험을 진행 중이라고 설명했다.

Ceramic.ai의 pay-per-query 모델에서는 참여를 선택한 발행자의 콘텐츠가 검색 결과에 나타나면 대가를 받는 구조를 시험한다. You.com의 접근은 에이전트가 필요한 특정 프리미엄 콘텐츠에 대해 사전 구매 약정 없이 요청 시 결제하는 방식이다. [원문 1](<https://techcrunch.com/2026/07/01/cloudflares-new-policy-pushes-ai-companies-to-pay-for-publishers-content/>) [원문 2](<https://blog.cloudflare.com/making-ai-search-smarter/>)

### Monetization Gateway와 x402 결제 절차

Monetization Gateway는 Cloudflare가 보호하는 웹페이지·데이터셋·API·MCP 도구에 과금을 적용하려는 계획이다. 발표 당시에는 고객 대상 대기자 모집이 열렸다.

계획된 결제 규칙은 경로·REST 메서드별 조건과 가변 가격을 지원하며, 인증되지 않은 요청에 대한 401 응답을 402 결제 안내로 바꾸는 방식을 포함한다. 대시보드·API·Terraform 설정과 원 서버 접근 전 엣지에서의 결제 검증도 도입할 계획이다.

Cloudflare가 설명한 x402 절차에서는 서버가 402 Payment Required 응답으로 가격·받는 자산·결제 목적지를 알린다. 클라이언트가 결제 증명을 첨부해 다시 요청하면 facilitator가 검증하고 서버가 자원을 제공한다. 일반 HTTP 요청·응답 안에서 교환하며, 금액은 판매자의 지갑으로 직접 정산된다. Gateway의 초기 결제는 스테이블코인과 x402를 사용할 계획이고, 에이전트 인증에 Web Bot Auth를 요구하는 선택도 제공할 계획이다. [원문 4](<https://blog.cloudflare.com/monetization-gateway/>)
