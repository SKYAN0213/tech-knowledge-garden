# AWS, Amazon Bedrock 기반 피싱 탐지 파이프라인 구현 방법 공개


AWS는 2026년 7월 3일(한국시간) Amazon Bedrock을 이용해 AI 생성 피싱 이메일을 분석하는 구현 방법을 공개했다. 기존 메일 인증에 발신자의 평소 행동과 업무 맥락을 비교하는 모델 분석을 더하고, 위험 점수에 따라 수신·격리·차단을 나누는 설계다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/how-amazon-bedrock-catches-ai-generated-phishing/>)

### 메일 인증 뒤 행동과 업무 맥락 비교

소개된 흐름은 먼저 SPF·DKIM·DMARC로 발신 서버와 메시지 인증을 검사한다. 이어 발신자의 평소 어휘·말투·요청 유형을 데이터베이스에 둔 기준선과 비교하고, 이메일 내용·조직의 업무 맥락·알려진 피싱 사례를 Amazon Bedrock Knowledge Bases에서 가져와 분석 프롬프트를 구성한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/how-amazon-bedrock-catches-ai-generated-phishing/>)

### 필터 설정과 메시지 처리

AWS는 Bedrock Guardrails로 개인정보를 가릴 수 있지만, 필터가 너무 엄격하면 검토해야 할 의심스러운 문구까지 분석 전에 막을 수 있다고 설명했다. 보안 분석에는 해당 콘텐츠를 평가할 수 있도록 설정하면서 다른 용도의 입력·출력 보호를 유지하고, 답변이 실제 이메일 내용에 근거하는지도 확인하는 방식이다.

콘텐츠 이상·행동 편차·맥락의 적절성 점수는 0\~100의 위험 점수로 합쳐진다. 안전한 메일은 수신함으로 보내고, 의심스러운 메일은 보안팀 검토를 위해 격리하며, 위험한 메일은 차단하도록 구성한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/how-amazon-bedrock-catches-ai-generated-phishing/>)

### 검토 결과를 다음 분석에 반영

보안팀이 오탐으로 확인한 결과는 발신자 기준선을 수정하는 데 사용한다. 확인된 피싱과 정상 메시지는 검증된 예시로 쌓아 다음 프롬프트에 포함하고, 보안팀의 피드백으로 분석 지시를 다듬는다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/how-amazon-bedrock-catches-ai-generated-phishing/>)
