# AWS, 여러 계정의 Health 이벤트를 MCP로 조회하는 Chaplin 구조 공개


AWS는 2026년 6월 26일(한국시간), 여러 AWS 계정의 운영 이벤트를 자연어로 분석하는 Chaplin 구현 글을 공개했다. 이 시스템은 AWS Health 데이터를 모으고 Amazon Bedrock 기반 분석 기능을 MCP 도구로 제공해 Claude Code·Kiro CLI 같은 클라이언트에서 조회하도록 구성된다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/build-self-service-aws-health-analytics-to-find-actionable-health-insights-with-ai-agents-powered-by-amazon-bedrock/>)

### 계정별 이벤트 수집

각 계정의 AWS Health 이벤트를 EventBridge·Lambda와 교차 계정 IAM 역할로 수집한다. 중앙 계정의 S3에 저장한 이벤트는 Lambda를 거쳐 DynamoDB에 적재된다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/build-self-service-aws-health-analytics-to-find-actionable-health-insights-with-ai-agents-powered-by-amazon-bedrock/>)

### 집계와 설명의 구분

요약 도구는 DynamoDB를 직접 조회해 서비스·상태·분류·지역별 집계를 반환한다. 상세 도구는 조건별 이벤트를 조회하고, AI 분석 도구는 Strands Agents와 Bedrock으로 질문과 이벤트 설명을 해석한다.

규칙 기반 패턴 분류를 먼저 적용하고, 맥락 분석이 필요한 비정형 설명에 모델을 사용한다. AWS 글의 조회 화면과 계정별 수치는 실제 고객 성과가 아닌 샘플 데이터 예시다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/build-self-service-aws-health-analytics-to-find-actionable-health-insights-with-ai-agents-powered-by-amazon-bedrock/>)

### 접속과 배치

MCP 클라이언트는 읽기 전용으로 연결한 AWS 자격 증명과 최소 권한 IAM 역할을 사용한다. 로컬 MCP 서버 설치 또는 Lambda 서버와 로컬 프록시 조합으로 배치하는 경로를 제시했다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/build-self-service-aws-health-analytics-to-find-actionable-health-insights-with-ai-agents-powered-by-amazon-bedrock/>)
