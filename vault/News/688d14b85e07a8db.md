# GitHub Actions, 작업별 캐시 읽기·쓰기 권한 설정 지원


GitHub는 9월 10일 모든 요금제에 GitHub Actions의 cache-mode 설정을 정식 제공한다고 발표했다. 워크플로 또는 작업 단위에서 캐시 읽기, 읽기·쓰기, 쓰기 전용, 접근 차단 중 하나를 선택할 수 있다. 작업 단위 설정이 우선하며, 재사용 워크플로는 호출자가 부여한 캐시 권한을 초과할 수 없다. [원문 1](<https://github.blog/changelog/2026-09-10-control-github-actions-cache-access-with-cache-mode/>)

### 이벤트별 기본 권한

pull\_request\_target 같은 낮은 신뢰 이벤트는 캐시 복원만 가능한 read가 기본이다. push 같은 신뢰 이벤트는 복원과 저장이 가능한 write가 기본이며, write-only는 저장만 하고 none은 접근을 차단한다. [원문 1](<https://github.blog/changelog/2026-09-10-control-github-actions-cache-access-with-cache-mode/>)

### 명시적 쓰기 설정은 기본값을 덮어쓴다

낮은 신뢰 이벤트라도 cache-mode를 write 또는 write-only로 명시하면 읽기 전용 기본값을 덮어쓴다. GitHub는 이 경우 캐시 오염 위험이 커질 수 있다고 설명하며 쓰기 권한에 대한 경고를 표시한다. [원문 1](<https://github.blog/changelog/2026-09-10-control-github-actions-cache-access-with-cache-mode/>)
