# AWS, Bedrock 추론의 분산·대체 모델·계정 격리 패턴 정리


AWS는 2026년 7월 1일(한국시간) Bedrock 추론의 지역 분산·계정 분할·모델 전환·부하 분산·테넌트 할당량 격리를 다룬 구현 지침을 공개했다. Bedrock의 기본 기능과 여러 모델을 연결하는 LLM gateway를 구분하고, 각 패턴의 구성 방법과 데모를 제시했다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/implementing-resilience-patterns-with-amazon-bedrock-and-llm-gateway/>)

### 지역 분산과 계정 분할

Cross-Region inference(CRIS)는 모델 트래픽을 분산하고 단일 리전의 할당량을 넘어 처리량을 확보하는 방식이다. 모델에 따라 여러 리전으로 동적으로 배분하거나 고정된 추론 리전을 사용하며, 모델·공급자 장애에 대한 failover나 재해 복구 기능은 아니다.

계정 분할은 각각 독립적인 할당량과 CRIS 프로파일을 가진 여러 AWS 계정에 요청을 나누는 방식이다. AWS는 계정별 경계를 이용한 작업 격리를 설명했다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/implementing-resilience-patterns-with-amazon-bedrock-and-llm-gateway/>)

### 대체 모델로 전환하는 조건

LLM gateway는 여러 공급자의 모델을 공통 API로 연결하고 재시도·대체 모델 전환·할당량 관리·감사 로그를 처리하는 프록시다. 주 모델의 요청 제한이나 장애를 기준으로 보조 모델에 전환하는 패턴은, 품질과 비용에 따라 모델을 선택하는 Bedrock Intelligent Prompt Routing과 구분된다.

AWS의 LiteLLM 데모는 주 모델을 분당 3건, 대체 모델을 분당 25건으로 제한하고 동시 요청 10건을 보냈다. 주 모델이 3건을 처리한 뒤 나머지 7건은 대체 모델로 전환됐으며, 데모의 10건은 모두 완료됐다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/implementing-resilience-patterns-with-amazon-bedrock-and-llm-gateway/>)

### 부하 분산과 사용자별 할당량

부하 분산은 여러 모델 인스턴스로 요청을 나누는 방식이다. 지침은 기존 모델로 대부분의 요청을 보내면서 새 모델에 일부만 보내는 가중 라우팅과 A/B 테스트를 설명한다. 테넌트 격리는 사용자별로 독립적인 요청 제한을 두어 한 사용자의 할당량 소진이 다른 사용자의 배정량을 소비하지 않게 한다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/implementing-resilience-patterns-with-amazon-bedrock-and-llm-gateway/>)

### 데모와 운영용 참조 구성

AWS의 운영용 Multi-Provider Generative AI Gateway 참조 구현은 LiteLLM에 ECS·EKS 컨테이너 배포, 자동 확장, AWS WAF, 비밀정보 관리, CloudWatch 관측 기능을 더한 구조다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/implementing-resilience-patterns-with-amazon-bedrock-and-llm-gateway/>)
