# AWS, AgentCore 실행 추적으로 무한 루프·도구 오류를 찾는 절차 공개


AWS는 2026년 6월 30일(한국시간) Amazon Bedrock AgentCore Observability로 운영 중 에이전트의 반복 실행과 도구 호출 오류를 진단하는 구현 지침을 공개했다. CloudWatch 지표·추적·구조화 로그를 함께 보고, 오류율이 낮아도 토큰 사용량과 세션 시간이 늘어나는 무한 루프를 찾아내는 방식이다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/debugging-production-agents-with-amazon-bedrock-agentcore-observability/>)

### 정상 종료와 올바른 답변을 구분하는 추적

AWS는 문제를 품질·신뢰성·효율로 구분했다. 품질 문제는 실행이 끝났어도 답이 틀린 경우이며, 신뢰성 문제는 도구 오류나 상태 유실로 작업을 마치지 못하는 경우다. 지연·과도한 토큰 사용은 효율 문제로 분리한다.

OpenTelemetry 형식으로 추적·span 로그·지표를 내보내며 CloudWatch가 기본 수신처다. 같은 데이터를 Datadog·Grafana Cloud·Elastic Observability로도 보낼 수 있다. CloudWatch Transaction Search를 켠 뒤, 개별 실행의 추론 단계·도구 호출·메모리 조회를 따라간다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/debugging-production-agents-with-amazon-bedrock-agentcore-observability/>)

### 반복 실행과 권한 오류를 다르게 처리

무한 루프에서는 토큰 사용량이 많은 세션을 먼저 찾고 동일 도구 호출과 추론 패턴을 대조한다. AWS는 종료 조건을 명시하고 같은 행동이 세 번 반복되면 멈추는 로직을 넣는 예를 제시했다.

도구 오류는 인증 401·인가 403·입력 형식 400·리소스 없음 404·실행 오류 500으로 나누어 원인을 좁힌다. 인증·권한 오류는 Gateway 서비스 역할과 자격 증명을 확인하고, 입력 형식 오류는 에이전트가 전달한 값과 도구 스키마를 대조한다.

진단 쿼리는 대시보드와 경보로 옮기고, AgentCore Evaluators는 세션을 품질 기준으로 평가한다. 실행 경로를 기록하는 관측성과 답변 품질을 판단하는 평가는 서로 다른 단계다. [원문 1](<https://aws.amazon.com/blogs/machine-learning/debugging-production-agents-with-amazon-bedrock-agentcore-observability/>)
