# Hugging Face, Slack 대화와 작업 기록을 이어가는 내부 Moon Bot 구조 공개


Hugging Face는 2026년 6월 24일(한국시간), Slack에서 코드·로그·데이터를 조회하고 작업을 요청하는 내부 도구 Moon Bot의 구조를 공개했다. Pi 코딩 에이전트 SDK와 Kubernetes 실행 환경을 사용하며, 대화와 도구 호출 기록을 Hugging Face Buckets에 저장해 재시작 뒤에도 작업을 이어간다. [원문 1](<https://huggingface.co/blog/huggingface/moon-bot>) [원문 2](<https://github.com/pipecat-ai/pipecat>)

### 스레드별 작업과 기억

Slack 스레드마다 독립적인 에이전트 세션을 생성한다. 도구 호출 결과까지 담은 JSONL 파일과 스레드·세션의 대응표를 저장하고, 이어지는 메시지에서 필요한 세션을 내려받는다.

응답 Markdown과 세션 기록에 연결되는 버튼을 Slack에 제공한다. 과거 상호작용 기록은 별도 기억 도구로 검색하며, Markdown 스킬은 CLI 사용법과 코드베이스 관례를 전달한다. [원문 1](<https://huggingface.co/blog/huggingface/moon-bot>)

### 사용한 SDK

Moon Bot의 코딩 SDK는 Pi다. 별도로 인용한 Pipecat은 실시간 음성·멀티모달 에이전트를 만드는 Python 프레임워크다. [원문 2](<https://github.com/pipecat-ai/pipecat>) [원문 1](<https://huggingface.co/blog/huggingface/moon-bot>)

### 권한과 쓰기 경로

Okta 그룹으로 사용자의 접근 등급을 결정하고 등급마다 별도 Linux 사용자와 자격증명 환경을 둔다. 외부 서비스 키는 프록시가 서버 측에서 삽입하고, 에이전트 실행 환경에는 원래 키를 전달하지 않는다.

PR·이슈 쓰기는 에이전트의 셸이 아니라 봇 프로세스의 전용 도구가 수행한다. 이 경로에서 짧은 유효기간의 GitHub App 토큰을 사용하고 에이전트 도구 호출에는 토큰을 노출하지 않는다. [원문 1](<https://huggingface.co/blog/huggingface/moon-bot>)
